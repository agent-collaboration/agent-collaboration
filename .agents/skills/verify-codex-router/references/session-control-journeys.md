## Case verdicts

| Case | Pass condition | Wrong behavior it rejects |
| --- | --- | --- |
| `savedModeRestart` | Run `sessionControl.restart: {phase:"seed",record:...}` and retain its prepared record. Use the runtime's `reopen.json` directive. At Host B set `phase:"reopen"`, use the record and its SHA-256, and bind B's new epoch and gate. The same store and Session reopen. The vendor reports the saved mode or the caller reports the observed difference and its reason. The new prompt reaches the wire once and saved setup stays byte-identical. | Restore silently leaves the harness in its default mode, rewrites saved setup, reuses the old Host or repeats the prompt. |
| `unansweredReopen` | Forward A's exact restore and hold its response. B's probe completes within that window. A returns the typed deadline with retry guidance, leaves no prompt on the wire and returns inactive. A deliberate same-ID retry reaches restore after disarming. | Restore hangs, blocks B, leaves A active or turns the waiting operation into a prompt. |
| `unansweredClose` | Materialize the session with a short prompt. Forward an advertised close while idle, withhold its exact response and require unknown remote effect and local release. The same-ID reopen must either load and allow one prompt or give explicit missing-session guidance. | The Session sticks in closing, claims confirmed remote closure, or hides an authoritative missing-session result behind a generic error. |
| `unconfirmedCancel` | Forward the exact prompt and cancel notification. Hold the terminal reply and require terminal Unknown, local close, and same-lifetime refusals naming the original operation. Explicitly reconcile it, confirm the effect still reads Unknown, then reopen and require one fresh prompt dispatch. A real harness that already ended before the cancel crossed the pipe is inconclusive. | Cancel acknowledgement is treated as confirmation, the durable unknown disappears, the Session stays loaded, or the refusal remains after reconciliation. Post-restart behavior has a separate two-epoch case. |

Every operation uses its own ID and waits for a product terminal response under a longer observer bound. In unanswered reopen the owning store also places B's completion before A's timeout. Use a fresh fixture store per independent case. Share the store only between the seed and reopen phases of saved mode.

## Evidence and limits

Keep the signed build qualification, root, process identity, source, Host epoch, provider package/version, public replies and row readbacks in the run evidence. The gate keeps an ordered received-frame ledger with forwarding or withholding dispositions in `wire.jsonl`. It records the raw replies for initialize, new and restore after excluding credential carriers. Payloads outside the setup, prompt correlation and operation evidence are omitted. Retain caller response fields as actually returned, including summary, differences, or the available reason fields. The four cases do not exhaust the U15 matrix.

Prompt evidence joins the case's unique token from its exact outgoing ACP prompt to inbound user-message chunks on the same Session during the measured turn. The provider's model response and history replay cannot supply that witness. An unaffected completed turn can decide whether a match was present. The gated cancel records its token and any echo but cannot decide absence from that cut. Inspect `_meta.steering.supported` in raw initialize and session replies alongside the public capability report. The raw advertisement establishes what was offered on the connection.

Budget two synthetic no-tools submissions for saved-mode restart and two for unanswered reopen. Unanswered close uses two, or one when `closePrimer: false` starts from metadata-only creation. Unconfirmed cancel expects two provider submissions and reserves one more in its plan for the refusal probe, in case a wrong build dispatches it. If the probe is admitted, the driver stops before the successor prompt. Obtain an owner-approved aggregate cap before launch. Stop only owned processes, settle the existing operation IDs, and preserve the recordings outside runtime storage.
