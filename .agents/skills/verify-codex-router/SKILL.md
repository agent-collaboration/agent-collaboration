# Verify Codex Router

Drive an isolated debug Router and its real owning Host, preserving normal Codex home. Reusable TypeScript drivers live in `verification/observations/`; native fixtures and checkers stay with their permanent tests. Run from the repository root.

IF the assignment covers board-upgrade, load [board upgrade](references/board-upgrade.md) and use its CLI/isolated Tokio launch, readiness, interruption and cleanup route. Return source and executable hashes, the supplied-copy classification, actual reports and owning readbacks, counts and pending obligations. That route uses fixture Access and requires no model input.

IF the assignment covers central-runtime, load [central runtime](references/central-runtime.md) and return its source-pinned commands, counts, executable hashes and uncovered obligations. It uses central's existing conformance harness. IF the assignment covers central-staging preparation, load [central staging](references/central-staging.md) and return the retired/unavailable result and unobserved OB7 cases. A build never authorizes a staging request or deploy.

For model-free private Tailnet MCP/board verification, follow the separate [Tailnet journey](references/tailnet-mcp.md) and its HostPlan/BoardPlan launch. That journey is draft until exercised on a declared real target.

For Sessions/Quota presentation, follow [compiled TUI journeys](references/tui-journeys.md). Reusable source-bound drivers use prebuilt compiled PTY fixtures and retain original wterm DOM PNGs from actual PTY bytes without starting a Host/provider session. Declare exact source/build/tools, plan, viewport and owned cleanup; fixture evidence is not public/provider proof. Narrow-width and short-height desktop proxies are the adopted phone scope; actual iPhone hardware is waived. Run results/history belong in the task evidence under `tmp/tui-verification/`, not this recipe.

The [input-consumption and returned-outcome readers](references/input-consumption-readback.md) validate the published core wire and U4/U5 source split. Reader sensitivity is qualified; actual S6b producer-byte integration remains pending.

The [optional sessions fixture receipt transport](references/sessions-fixture-receipts.md) forwards one explicitly owned directory through both fixture launch paths. Transport qualification does not establish S6 producer contents or product input/effect outcomes.

Future S9 toolbar/menu/dropdown/account-action/refresh cases are [authored new-entry drafts](references/s9-new-entry-journeys.md), explicitly absent at base until S6/S7. Their schema/oracle checks launch no TUI and establish no product pass. Claude stopped-session Details is Open-only under the 2026-10-30 correction; Open resumes the same session with saved settings and attaches.

The [Ghostty input harness](references/ghostty-input-harness.md) stages layer C through actual PTY mode readback, a spec-derived key encoder and example Ghostty keybinds, plus SGR1006 press/release/wheel input. It remains unobserved on the S9 product; physical hardware, other app/OS keybinds and real Ghostty rendering remain outside its proof.

**Observed locally:** genuine Claude Question/Approval callbacks, actual Session test decisions, marker execution, owning SQLite reopen and exact cleanup on Sunclaw. The first unreachable native-Approver case remains negative evidence. **Portable cold entry and Cursor remain draft:** endpoint/settings/tool parameterization has structural and retained-Claude qualification; no Cursor model input or callback run has happened. Use [Cursor qualification](references/cursor-provider.md) before its first input. No successful journey is rerun merely to refresh the recipe.

## Launch and readiness

Get the caller's declared source, normal signed artifacts, allowed debug root/profile, provider executables and private evidence directory. This recipe adds no permissions. Use the actual host permission mechanism if authorized process/state access is sandbox-blocked; do not switch identities, roots or transports around denial. Keep production and other controllers untouched.

Build verification binaries in the declared worktree's normal `target/debug`, with no per-run or scratch Cargo target override. The standalone `board_upgrade_native` workspace uses its own `scripts/verification/board_upgrade_native/target/debug` when the commission grants that build root. After all consumers settle, clean only the owned target with the repository's Cargo cleanup policy; a shared tree's other build owner must remain undisturbed. Keep receipts and other evidence outside every `target/`.

Install the pinned dependencies with `pnpm --dir verification install --frozen-lockfile`. Read `RuntimePlan` in `verification/observations/runtime-plan.ts`. Put its JSON in the run's private evidence directory and set `RUNTIME_PLAN` to that path. Required fields: `repository`, `source_head`, `qualification`, `router_root`, `evidence`, `port`, `expected_version`, `profile`, `codex_config`, `native_cwd`, `claude_node`, `claude_adapter`, `claude_executable`, `cursor_executable`, timezone-aware `deadline`. `profile` and `codex_config` name the saved normal Codex debug profile and `config.toml`; both are read-only. Select a fresh free loopback port, excluding every caller-protected port. `native_cwd` must name an existing directory with an exact preexisting trusted project entry in normal config.toml; preflight reads it and refuses to create or broaden trust. Use that cwd for native bootstrap/recipient creation; provider work stays in the private lifecycle workspace. Resolve installed executables on this machine. `claude_executable` is an expected binding: preflight requires its canonical path to equal the first qualified global `claude` on the unchanged Host PATH and records that canonical path and SHA256 in `driver-binding.json`. It does not override the Host's selection. `runtime-qualification.ts` mirrors `global_claude_executable.rs`, including package search directories, transient package targets, SDK exclusions and effective execute access; a normal global Claude Code package target remains eligible. Mismatch fails before any Router requester. Qualification also supplies exact normal binary paths/hashes and empty `testGuardFeatures`; the caller declares any source/build equivalence. Never copy old run IDs or machine install paths into a portable plan.

```sh
node verification/observations/owned-runtime.ts "$RUNTIME_PLAN"
```

Use a persistent execution context with the actual required host grants and a declared signed binary implementing the isolated debug Host's in-memory endpoint-only projection. The helper checks source, strict debug signature/hash, process access, root ownership, database consumers and the selected free port before launching. It retains one Router across Host A/B. Preserve an exact live OS requester if approval is pending; never spawn another. The binary validates the saved profile at its own port and projects only its endpoint to the selected port. The apparatus never writes or restores either Codex configuration file.

`codex-home-before.json` records both files' SHA256, size and modification time before any requester. `configuration-*.json` records read-only comparisons before each Host launch, at readiness and after Host shutdown; cleanup records the final comparison. The saved profile stays strict: every boundary requires its complete fingerprint to match. For config.toml, retain whole-file fingerprints as observations and only TOML table headers, raw-section SHA256, repeated-table occurrence and change classifications; never retain configuration values. Compare each section's enclosing array-element association as well as its text hash: moving a child table between entries counts as a section change. Only changed desktop tables and project tables unrelated to this run are permitted. Any changed section naming a run path or actual run identity, any other changed section, malformed TOML or unreadable state stops dependent work and stays untouched. A preexisting trusted cwd entry may remain identical. The allowed external section classes do not identify their writer. Apparatus write-open controls still forbid writes to either normal file.

Wait for `router-ready.json` and `host-A-ready.json`, then run the independent read-only check:

```sh
node verification/observations/owned-runtime.ts "$RUNTIME_PLAN" --check
```

It checks recorded PID/UID/birth/group/executable, binary hash, health version and same-root Host publication. Health is readiness, not credential usability; a genuine provider journey proves that separately. `/v1/models` is not a Claude credential oracle. Launch owners: `crates/codex-router-cli/src/host_command/{mod,foreground_launch}.rs`, `crates/codex-native-integration/src/debug_profile_projection.rs`, `crates/codex-router-host/src/lifecycle_owner/startup_convergence.rs` and `claude_provider_launch_environment.rs`.

## Reopen and cleanup

After exact callback/tool/turn and operation settlement, close only the synthetic provider Sessions; verify their terminal/applied/confirmed close operations. Write `reopen.json` in runtime `evidence` to request Host A close and B startup. Host B starts only after that explicit request and within the allocation deadline. Deadline expiry during readiness, waiting or between phases, and any unexpected Host exit (including exit 0), produce a non-null lifecycle failure and cannot authorize B. `stop.json` requests cleanup without a reopen. Require A exit 0/no errors/no remaining owned processes, then B readiness with a new epoch and the same service/root/signed binary. The lifecycle verifies that A's database consumers, sockets and publication are gone before B starts; it keeps the external Router alive.

`interaction-readback.ts --help` reads scoped rows and the singleton global revision in one read-only transaction. `--before` accepts only identical answered/decided records, creation instants, database root and revision. Query the same exact IDs publicly through Host B too. Exact cancelled-row equality can prove negative-history persistence, never successful callback consumption.

For exact recorded-inventory cleanup, `process-inventory.ts --help` provides independently runnable `--capture-root <this-run-host-started.json> --inventory-output <fresh-file>` and `--settle-inventory <recorded-file>` actions with the runtime plan. It checks stable PID/UID/birth/group/executable, excludes mutable parent from identity, acquires descendants only from matching roots, and tolerates an independently disappeared PID. Capture again after all callers settle before planned cleanup. Keep the separately retained Router out of Host A's inventory. No inventory grant permits signalling an unrecorded process.

After B readback, write `stop.json` in runtime `evidence`. Inspect `lifecycle-settlement.json`: require no remaining owned processes/cleanup errors, `configurationGuardPassed: true`, an identical saved-profile fingerprint and surviving evidence. `codexHomeUnchangedExactly` separately reports literal whole-file equality and may be false only when the config section guard admits the observed external section classes. Keep the before/after whole-file fingerprints and label the writer unattributed. No restore is attempted, including after an external edit. Stop only exact recorded report-server processes after fresh identity checks and close only the owned tab. Never kill by process name or remove evidence directories. Retain every failed/uncertain operation ID.

Provider controls register actual returned Session/operation/interaction identities in private `guard-identifiers.jsonl`; native correlation registers its exact supplied thread/turn/Push IDs. Keep this ledger in the runtime evidence directory and never copy another run's identities. Table checks reject a changed section naming any registered identity. Typed views validate only used fields; complete raw snapshots remain authoritative for exact equality, including unknown fields and nanosecond timestamp strings. Controlled lifecycle tests use only recorded harmless local subprocesses and a synthetic pipe fixture; those results never count as native/provider runtime proof.
