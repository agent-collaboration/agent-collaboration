# Router database retention and space recovery

The standard history window is **two calendar months**, measured with calendar-month arithmetic. Current state and pending work remain available. The proxy's previous-response affinity is the explicit 30-day exception.

At startup, the Host imports `approval-routes.json` into `interaction.sqlite` in one transaction and removes it after commit. Invalid route JSON refuses startup and is kept for recovery. The Host deletes `approval-history.json` without reading or migrating it; typed approval and question history stays in `typed_interaction_history`.

The maintenance path validates stored state before deletion and processes bounded batches. Interaction answers, read contexts, submission epochs, and eligible terminal pushes are pruned in one transaction. A parent push stays while its send answer, cancellation, scheduled retry, or poll work is pending. The pinned `_fleet_sync_*` tables remain library-owned; their retirement follows the library's acknowledged frontier.

`message_send_answers` and `local_cancel_deliveries` use nullable `settled_at_ms` values: NULL means pending. Existing completed rows receive their migration-time timestamp, so the two-month window begins at rollout for those rows. Duplicate sends retain their recorded answer throughout the two-month window.

## Space recovery

### Native SQLite files

`state.sqlite`, `automation.sqlite`, `session-registry.sqlite`, and `provider-operations.sqlite` use WAL and the shared `sqlite-storage-maintenance` crate. New files set `auto_vacuum=INCREMENTAL` before their first schema write. On existing files, the opener checks the mode and, if conversion is needed, checkpoints WAL, sets `auto_vacuum=INCREMENTAL`, then performs one full `VACUUM` and verifies the resulting mode. It requires free space equal to twice the database-plus-WAL size. This rewrites the database once and can hold its SQLite writer for the duration; the conversion path does not wait on a busy database and defers when it cannot safely proceed. Owners call bounded `PRAGMA incremental_vacuum(64)` steps after retention work, followed by a PASSIVE checkpoint.

SQLite only applies `auto_vacuum` when it is selected before tables are created, or after a full `VACUUM` converts an existing file. See SQLite's [auto-vacuum pragma](https://www.sqlite.org/pragma.html#pragma_auto_vacuum) and [VACUUM documentation](https://www.sqlite.org/lang_vacuum.html).

The owning maintenance paths are [proxy maintenance](../../crates/codex-router-proxy/src/maintenance_actor.rs), [automation retention](../../crates/collaboration-runtime/src/automation_retention_worker.rs), [lifecycle journal retention](../../crates/lifecycle-observation/src/journal_retention.rs), and [provider-operation retention](../../crates/codex-router-host/src/collaboration_runtime/provider_retention.rs). The shared conversion and bounded step are in [sqlite-storage-maintenance](../../crates/sqlite-storage-maintenance/src/lib.rs).

### Turso files

`interaction.sqlite` and the Router-local fleet/cache/outbox/cursor files explicitly select WAL where their openers can set it. Project, install, and read-copy files are opened through the pinned Turso stack. Retention deletes pages for reuse, but the current pinned `sqlx-turso` driver does not set Turso's experimental vacuum option and does not expose `VACUUM`; Router openers do not enable `auto_vacuum` for these stores. A bounded isolated Turso probe showed that direct experimental VACUUM can shrink a local file while retaining rows and the tested CDC prefix, but it did not prove the complete project replication/acknowledgement path. Therefore no Router Turso store runs VACUUM automatically, and replicated project files remain unvacuumed pending an owner-approved driver change and full replication proof. See the [pinned driver limitations](https://github.com/agent-collaboration/agent-fleet-sync/blob/b9da4b5f230f81430fdf1140fbb634cf64decd8e/crates/sqlx-turso/README.md#L88-L97).

For disposable board read copies, deleting a released generation removes its whole database file set. This avoids retaining freelist pages across generations.
