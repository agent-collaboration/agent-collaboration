# Verification Design: D3, local cleanup

How D3's requirements will be shown to hold. A plan: nothing here has been observed. Upstream: [R23–R29](../specification/local-storage.md), [program design](../program-design/d3-local-cleanup.md).

**Target for every row:** a debug Router built from the D3 branch, each with its own debug root, upgraded from **populated** D1 stores, never empty ones. The fixture is a debug root that ran D1's journeys (O1, O9, O11) plus approvals, a question, provider operations on `codex-local` and `claude-local`, an enrollment, and a snapshot install. It's frozen as a copied debug root in the verification harness, not committed. Luna sessions on the debug Router only; the Claude provider runs on Haiku after asking the owner. A local Tokio central serves the enrollment, and staging Cloudflare for the central parts: D3 adds the Fleet **switch machine id** call, and it changes hook history in Central project objects.

## Observations

| ID | Observation | Decides |
| --- | --- | --- |
| <a id="q1"></a>Q1 | **Schema readback after upgrade.** Open every scoped store and list every table, column, key and CHECK. Every Router table matches its concern prefix. Every table, Router and library, has a UUIDv7 key and both timestamps, apart from SQLx migration tables, which match SQLx's own shape. The only CHECKs are boolean, and the legacy Mailbox tables are absent | R23, R24, R25, R29 |
| <a id="q2"></a>Q2 | **Row readback after upgrade.** For every rebuilt table, the row count and each row's business columns equal the pre-upgrade copy. Every new key is UUIDv7, and every timestamp is valid. Hook migration history keeps every version, with its checksum as bytes. A seeded invalid stored value (a non-UUIDv7 key, or a timestamp of `0`) is refused on read with a typed error. A new approval created after upgrade has a UUIDv7 Router request id. Hook history: upgrade populated history, initialize the same hook twice without re-running its DDL, apply one new hook migration, and refuse a changed or malformed checksum with rollback, on a Machine project store and on a Central project object (Tokio and staging) | R24 |
| <a id="q3"></a>Q3 | **Behavior is unchanged.** After upgrade, the existing approval, question, `message send`, `wake` and provider-session journeys pass as before, on the upgraded root | R23 |
| <a id="q4"></a>Q4 | **Kind-aware removal.** **needed:** the D1 debug mail clock (`debug_mail_clock.rs`) on the Router. Seed a copy of each message kind (direct, wake, schedule run, board activity) plus approval and question records, including a Message received late, one settled near day 60, and one with a pending retry, poll or unresolved send. At day 59 after each Message's creation all are present; after day 60 the message copies are gone, their pending work has ended as expired, and `message show` no longer shows them. Approvals and questions remain until today's two-calendar-month rule removes them | R26 |
| <a id="q5"></a>Q5 | **JSON files moved.** After upgrade and restart: `fleet/enrollment.json`, `machine-session/state.json`, `machine-notice-progress.json`, `snapshot-install-attempts/*`, `service-identity.json` and `approval-routes.json` are gone, and their state reads back from the new tables (enrollment active, resume cursor kept, the in-flight install attempt reused rather than minted anew). Only `ports.json`, `providers.json`, `service.json` and schema bundles remain | R27 |
| <a id="q6"></a>Q6 | **Machine id switch with crashes.** **needed:** named crash points between every pair of stores in the switch, and before and after the service identity file is retired (debug builds only). Kill at each point and restart: the switch finishes. Pending approvals and known provider operations are intact, stored Messages verify their digest, and the manifest publishes the machine id. A new send to an address with the old id is refused with "this machine's id is now …". A message queued before the switch ends as "expired". On Tokio and staging: start from a real (old id, peer) enrollment; the switch leaves one enrollment at the new id with the old id as former, with no second peer and no deletion; a crash between the Fleet switch and the local rewrite resumes correctly. Lost reply: the Fleet commits the switch, its answer is dropped before the local record is durable, then the Fleet is unreachable across a restart. The Router doesn't serve under the old id; once the Fleet is back, it replays, finishes with one enrollment, and serves under P. Separately, an unreachable Fleet before the call is sent falls back to the old id safely. A populated debug root that has **never enrolled** upgrades with no Fleet credentials: it keeps its local interaction state, adopts its UUIDv7 peer id as its active id, opens its local surface, and its later first enrollment uses that id | R28 |
| <a id="q7"></a>Q7 | **Old-id subscription ends.** A subscription and a watch whose reader is a session on Machine M, in a project held by another Router. Switch M, restart and rescan the holder, add activity: no delivery to the old reader is produced, and a new subscription under M's new id works | R28 |
