Moving each machine to its UUIDv7 id means rewriting stored session addresses that carry the old UUIDv4 service id. Local stores are rewritten at upgrade. But project content also stores session addresses (thread participants, watches, actors), it replicates between machines, and project tables are out of scope.

  • A (recommended): ended, like wakes. Frozen content keeps the old id as history, and the Fleet records former_service_id so old records still show the right machine. What stops working at cutover: (1) messages still queued with the old id: the Router first stops new sends and lets its outbox drain, and anything left after that expires with the sender told “expired”; (2) subscriptions and watches whose reader carries the old id lapse, and agents subscribe again, the same way you chose for wakes (“no moves, we just message the agents”). Project content stays untouched.
  • B: carried over. Rewrite the live reader references in project content (subscriptions, watches) so they keep working, and re-issue queued messages under new ids. Cost: a coordinated change of replicated project content on every machine and in central (actor identities are UNIQUE; project mail handoffs carry content hashes), re-sent messages arrive as new messages, and project tables come into scope.
