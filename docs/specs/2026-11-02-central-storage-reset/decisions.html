Central storage reset: decisions

What is decided, what is still open, and the code it rests on. Code facts cite codex-router origin/main fb3cf6b5 (0.1.121) and the delivery library agent-fleet-sync v0.4.0 (b9da4b5). Earlier notes and designs are not used as evidence.

Everything below is decided. Next: the design set and the details of D1.

The target

Central is one Fleet object plus one object per project. Every machine has an inbox and an outbox, and every message and notification travels through them. A message from A goes out of A's outbox, Fleet routes it straight into Fleet's outbox, and Fleet's outbox delivers it to B's inbox. Fleet has no inbox. Fleet's own messages (automation firings, create-session requests) leave through the same outbox. Every machine keeps one WebSocket to the Fleet object.

Today, for comparison: one Connection and one Mailbox per machine, and Fleet cannot send

Central has five kinds of object (crates/collaboration-central-core/src/core_contract.rs:36): Fleet and Registry once each, a Connection and a Mailbox for every machine, and a Copy per project. A message's sender can only be a session, a human or a project (crates/collaboration-mail-protocol/src/mail_content.rs:18).
