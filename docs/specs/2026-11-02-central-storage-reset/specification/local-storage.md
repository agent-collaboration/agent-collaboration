# Specification: local-storage (D3)

What must be observably true of each Router's own storage after D3. Entities: [E3](entities.md#e3), [E8](entities.md#e8), [E13](entities.md#e13), [E14](entities.md#e14). Requirements: [U7](../requirements/mail.md#u7), [U9](../requirements/mail.md#u9), [U11–U13](../requirements/local-storage.md). Re-anchored to Router main `9ad3c0db0` and library `30371bf` (evidence `tmp/d3-inventory/2026-11-06-local-stores.md`).

**Scope.** The Router-owned stores, meaning message, approval and question history, provider operations, session registry, Fleet cache, Fleet outbox, board cursors and UI preferences, plus the library tables inside them. **Not in scope:** the model proxy's accounts, quota and routing store (protected by `AGENTS.md`), project stores, and everything automation (D4a, D4b).

| ID | Obligation | Failure expectation | Proof obligation | Basis |
| --- | --- | --- | --- | --- |
| <a id="r23"></a>R23 | Every table the Router owns starts with one prefix naming its concern. Approval and question tables are renamed too, and their behavior is unchanged. The library's `_fleet_sync_` names stay | A table whose name mixes location, encoding or two concerns doesn't exist after D3 | After upgrade, list every table in every scoped store: each Router table matches its concern prefix, and approval and question journeys behave as before | U11 |
| <a id="r24"></a>R24 | Every table in the scoped stores, Router and library, has a UUIDv7 primary key and `created_at` and `updated_at`. An existing UUIDv7 key stays. Every id the Router itself generates in these stores, such as a new approval request id, is UUIDv7; ids made by Codex, Claude and other tools stay theirs, and ids already stored aren't rewritten. Migration history tables we own, including the library's hook migration history, have SQLx's migration columns plus a UUIDv7 key and timestamps (D1's journal shape); tables SQLx creates itself keep SQLx's exact shape | A stored value that isn't a UUIDv7 key or a valid timestamp is refused when read, never silently coerced | Schema readback of every table, a row readback after a real upgrade of populated stores, and a new approval created after upgrade whose Router request id is UUIDv7 | U7, the owner's "match the standards of the systems we use" |
| <a id="r25"></a>R25 | The only SQL CHECK constraints in the scoped stores are boolean (`0` or `1`) | n/a | Schema readback lists every CHECK: each one is boolean | U13 |
| <a id="r26"></a>R26 | Every local copy of a Message (a direct message, a wake, a schedule run, board activity) is removed 60 days after the Message was created, whenever it was received or settled. Work still pending on an expired Message ends as expired rather than keeping the copy. Approval and question records keep today's retention | A copy older than 60 days isn't shown, and a Message older than 60 days isn't accepted (D1's R13) | With an injected clock, copies of each message kind are present at 59 days and gone after 60, including a Message received late, one settled near day 60, and one with a pending retry, poll or unanswered send; approval and question records follow today's rule | U9; local-storage "Not asked for: changing their retention" |
| <a id="r27"></a>R27 | Router state lives in SQLite. A JSON file remains only with a stated reason: owner-edited configuration (`ports.json`, `providers.json`), the published discovery manifest, and generated immutable schema bundles. Enrollment, machine-session resume and notice progress, and install attempts move into the Fleet cache store; the legacy approval-routes importer and the service identity file are removed | A moved file that is still present after upgrade is never read again | After upgrade and restart, each moved state survives and its old file is gone; the files that remain are exactly the listed ones | U12 |
| <a id="r28"></a>R28 | Each Router identifies itself everywhere new by its one UUIDv7 machine id. The old service id remains only as the Machine's former id, for labeling history. A Session address naming the old id is refused for new routing with "this machine's id is now …" | **Owner, 2026-11-03 ("yes they end"):** Messages queued before the switch, and subscriptions and watches whose reader names the old id, end at the switch. Senders see "expired", and agents subscribe again. A crash during the switch resumes where it stopped; pending approvals and known provider operations stay intact, and stored Messages still verify their content | Starting from a real enrollment on both central backends, the Fleet records the same Machine under its new id with the old one as its former id, without a second machine or a deletion. Kill the Router at each step of the switch: on restart it finishes, with approvals and provider operations intact and old Messages still verifying. A new send to an old-id address is refused with the new id, and an old-id subscription stays ended after its project holder restarts | U7 ("v7 id only for machines") |
| <a id="r29"></a>R29 | The library's unused Mailbox tables are gone from every Machine store | n/a | Schema readback after upgrade | U11, U7 |

**Not decided here:** the exact table list and each table's typed columns. They go on the D3 table page for the owner before any query is rewritten, as in D1.
