D1 review: overview, changes, design and decisions

The D1 design holds. Building it surfaced five places where my design was wrong or incomplete. Each one is now fixed or decided, and none of them changes the overall shape. D1 is not PR-ready yet: the two-Router run, the cutover tool and staging haven't run. This page is the one place to check the design, what changed and what still needs you. The central storage reset Lead wrote it, and the Fleet access Lead concurs (design commit e9471dc79, with its two wording changes folded in).

1. Remote session on an offline machine (explained under “Open decisions” below): queue it, or refuse it. 2. Staging login and Touch ID, but not yet: only once the cutover tool passes on the isolated test central, and I'll ask then. The debug Router is being started now under your go-ahead.

The design as built

Each organization has one central Fleet store, plus one store per project. Each machine has an inbox and an outbox. Central has an outbox only. A message travels like this:

A saves the message, then sends it to central.

Central checks the sender and admits the message once; a repeat send gets “already have it”.

B saves the message first, then says “got it”. If B is full, central retries later.

B reports delivered or refused; central tells A, then drops the content and keeps a small record.

Every message has one UUIDv7 id, created by the sender. That id is the key of A's outbox record, of central's record and of B's inbox record, and all three are removed 60 days after the time in that id. Nothing else is removed by this rule. Each Router has one store for its link to central (stores.html, agreed with Fleet access).

Bugs found and fixed

Paired Verifiers, the Advisor and the Implementers found these, and each was fixed where the code that owns it lives. No test was weakened to get past one.

  • Migrations accepted corrupt old rows, and new ids weren't checked on read (library 9cac5fd).
  • One migration dropped an index, so the Router refused its own store (library 0f5007a).
  • Over-long SQL expressions overflowed the stack in writes and in all four library migrations (library 0f5007a, f616005, 7b69ca0; v0.4.0 files untouched).
  • The Cloudflare Worker build was 551 MB, over its limit; it's now 302 MB (central 1962b04b9).
  • A project create could be cancelled by its own grant notice (Router d46b9e8d6).
  • Messages that existed before the upgrade would never be removed. A once-per-store startup backfill now handles them (library 1e76a3f, Router uncommitted).
  • The sender never got “delivered”, because central's status wake was dropped. The cause is found; central's fix is in progress.

Open decisions

Your decision (2026-11-03): refuse for now. It is marked as a temporary workaround in the D2 design (R18 and its failure case) and, when it is built, in a code comment at the refusal, until remote start is redesigned.

The situation: an agent on your laptop asks for a new session on your desktop, and the desktop is off or disconnected right then.

Queue (D2's current design): central keeps the request in its outbox. When the desktop reconnects, possibly hours later, the session gets created and the asker is told then. If the desktop never comes back within 60 days, the asker is told “expired”. You gain: nothing is lost, and it works with machines that sleep. You pay: a session can appear much later, when the asking agent has moved on.

Refuse (Fleet access's current design): central answers “that machine is offline” straight away, and nothing is kept. You gain: an immediate, simple answer, and nothing surprising later. You pay: the asker has to try again when the machine is online.

Recommendation (central storage reset Lead): refuse, for now. A remote session matters while the asker is waiting for it, and a late surprise session is worse than a clear “offline”. Queueing can come later if you want it. Fleet access Lead: also refuse, for now. A remote start is checked against the machine's current enrollment and permissions when it's asked. A queued one would need the same checks again when it's delivered, days later, plus a rule that it never starts twice. That's real extra machinery for a case nobody has asked for yet. If you choose queue later, both designs change together.
