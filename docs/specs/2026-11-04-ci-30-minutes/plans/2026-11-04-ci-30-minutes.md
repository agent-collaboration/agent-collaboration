## Goal and scope

Make the workspace nextest invocation start the right tests first and run 8 threads, without changing which tests run or what they prove. Then measure whether the PR's CI run meets 30 minutes.
- **In scope:**
  - the read-only profile tool;
  - priority overrides and `test-threads` in `.config/nextest.toml`;
  - the causal fix for `oversized_initialize_frame_is_rejected_and_reaps_owned_process`;
  - a causal fix for any other test that fails only under the new scheduling.
- **Non-goals:**
  - turning the remaining run-alone tests causal. That's a follow-up after this measurement, with the D1-touched areas after D1 merges;
  - ratchet speed;
  - crate splits;
  - options B and C. Those need the owner's Q1.
- **No version bump:** CI and test-only changes ship nothing to users, so the AGENTS.md release rule doesn't apply.

## Slices

### S1 · Profile tool (contract, consumed by S5)

- **Reads:**
  - Program Design "Entity binding" (the `InvocationInventory`, `InvocationProfile` and `ProfileResult` shapes) and "Components" (`ci-test-profile`);
  - Verification Design O2;
  - evidence `tmp/design-workflows/2026-11-04-ci-30-minutes/concurrency.ts` (prototype; not copied as-is).
- **Writes:** `verification/tooling/ci-test-profile.ts`, `verification/tooling/ci-test-profile.test.ts`, and small log fixtures under `verification/tooling/fixtures/`.
- **Behavior:** reads a downloaded test-job log (strips the literal `^[[…m` colour codes), splits it by step into one inventory per nextest invocation (PASS and FAIL lines), checks each inventory against its own `Summary` line, then prints per-invocation profiles. A count mismatch returns `inventoryMismatch`.
- **Pre-change signal (the wrong behavior the tests must fail on):** a parser that mixes the quota step into the workspace step, or drops FAIL lines. The test fixture models #213: a workspace step of 3 PASS + 1 FAIL with `Summary … 4 tests run: 3 passed, 1 failed`, and a quota step of 2 PASS beside it. The tool must give 4 and 2, not 6 or 5.
- **Oracle:** each step's own `Summary` line.
- **Proof:** focused unit tests (table-driven: matching Summary, mismatched Summary, missing step, and overlapping intervals → concurrency minutes). Proof-layer names: `project silent`, so plain unit tests. Command: `pnpm --dir verification test` (the build machine).
- **Existing tests overlapping:** none.
- **Stop:** if real CI logs don't separate steps by name, return to the Lead (that changes O2).

## Risks and false greens

- The profile tool could agree with itself while miscounting. Guarded by the Summary check (S1).
- A priority filter could select nothing on D1 while its band still matches. Guarded by per-selector listing (S3).
- A "causal" fix could keep the race. Guarded by the delayed-start pair (S2).
- One fast CI run could be luck. R1 is checked again on the first main run. A large gap between the two is reported, not averaged.
- 8 threads could expose more load-sensitive tests. Each is fixed causally (S5), and the PR is not merged with a known flaky test.

## Stop and replan conditions

- The I/O-before-advance assumption fails: `program-design-gap`.
- A needed change to D1's blocks: return to the Lead, which coordinates with the D1 Lead.
- Any temptation to raise a deadline, shrink a fixture, add a retry or move a test into a run-alone group to get green: stop. That's forbidden by R4 and R5.
