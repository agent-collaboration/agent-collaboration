# Prove the unchanged CLI through the shim

This is planned implementation proof, not a record of feature execution. Inputs: [Requirements](requirements.md), [Specification](specification.md), [Program Design](program-design.md). The design uses source-verified public APIs; writing or reviewing it does not observe the future implementation.

## What the owner will see

- **U1:** Open `$` in unchanged Codex CLI against the Claude ACP session and see its advertised fixture skill before any model prompt. Initial metadata can arrive late without an error or a stalled client. Native Codex keeps its existing skill list.
- **U2:** Select one skill at the beginning or middle of normal Text, include distinct arguments and an image, and see Claude execute its own skill. Unrelated dollar text stays untouched. Unsupported provider combinations refuse clearly and send nothing; native Codex retains its native capabilities.
- **U3:** Run existing `/compact` and model-selection flows and see their native requests, actual provider effects and terminal lifecycle. Acknowledgement or a prose explanation is insufficient.
- **U4:** Ordinary chat, interrupt, approval, history and native Codex behavior remain intact. No-list/failed-metadata providers remain usable for chat.
- **U5:** The same runtime uses the default ACP and injected Claude implementations. Provider changes stay in provider code and constructor wiring.
- **U6:** The source/dependency diff has one new Rust adapter crate and one small same-process provider package, with no client fork, scanner, new store or extra agent process.

Implementation baseline: `cec135a85e924b4404eb4b552e8565ef5c0ea8f1`, or a later explicitly reconciled source head. Use a dedicated complete worktree, signed normal debug artifacts, unchanged `codex-cli 0.164.0`, isolated Host/root/socket and the pinned Claude provider integration: installed official library 0.81.0 / SDK 0.3.280. Keep normal Codex home, existing trust and production processes/settings unchanged. The private integration asset imports that qualified installed library; development dependencies do not become a second runtime SDK or a global provider installation. Exact source/build/client/library/native executable identities and the existing credential/capacity route must be checked by delivery preflight before provider input.

S2 is a lasting command journey observing compaction/model effects and native lifecycle. S3 is the existing ACP metadata/live-history journey and native Codex control. ## Smallest real boundaries

Pure token splitting, reference parsing, classification and error mapping use focused permanent tests. Producer/consumer metadata checks keep the TypeScript producer and Rust decoder real; manually duplicated JSON is not their only contract proof. Actor/hub tests keep real ordering while a list replaces a queued selection. S1/S2 establish actual selection and effects; a stub cannot close them.

The pinned `LegacyAppPathString` conversion and picker/submission source establish the absolute-reference design. Actual round-trip and native error rendering remain required delivery observations, not assumed passes. Native scope=System and enabled=true are the integration presentation, not alleged provider filesystem provenance. Do not discover provider files to manufacture those fields.

The current `verify-codex-router` index and ACP metadata recipe were read; its pinned live/history observer uses the actual native socket and public provider observation. S1/S2 additions are explicitly needed and lasting. Reuse that harness and declared-target discipline; do not resurrect the removed catalogue verifier. Reviewing this document observes none of its planned behavior.

Other client/library versions and platforms remain unobserved until selected by implementation/release scope. No release, Homebrew installation, staging or production replacement is part of this design request. Feature completion needs applicable quality checks and the real required interactions, with original outcomes, exits and cleanup evidence.
