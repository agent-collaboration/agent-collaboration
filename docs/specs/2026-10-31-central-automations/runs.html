On the receiving machine

The machine that gets a firing does exactly what it does today. A wake becomes the same ⏰ Router wake push in its session. A schedule run starts in its bound session, or in a fresh session in its folder, with the same instruction, model, effort and timeout, and a summary afterwards. What's new is that it reads these from its inbox instead of its own timer, refuses duplicates, and reports back.

Reporting back

Each state change (delivered, runStarted, runFinished with its summary, or failed with its reason) goes to central as a FiringReport through the machine's durable outbox. If the network drops, it's retried; central accepts repeats once. Central only accepts a report from the machine the firing was sent to. That makes schedule show from any machine say what happened.

The firing_receipts row is written before anything is delivered or started, keyed by the firing ID. The same mail arriving again finds the row and stops. A run row carries the same firing ID, unique, as a second guard.
