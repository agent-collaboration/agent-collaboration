Delivery plan

The design is reviewed and ready. The Advisor's final verdict covers all four documents. Open findings went 11 → 6 → 3 → 1 → 0, and the two raised by later additions are closed too. This page is the plan to build it: nine milestones, six parallel lanes, and a named proof for every promise. Building starts when you approve it.

Approve or change this plan. Nothing is built until you do. The database PR (M0) continues regardless.

Every helper runs on Sunclaw, created through the Station Chief, each in its own Agent Studio worktree. The Advisor is consulted at the central, receiving and migration boundaries. I integrate each lane at its gate.

What "done" means at each gate

  • Every change: a test that fails first, then passes; deliberately broken builds that must fail; lint and format clean.
  • Central: the full central package and conformance on both runtimes.
  • Router: the storage, runtime, service and Host packages.
  • Repository checks: the module-cycle check, the verification tooling, and file size limits.
  • The real proof: the two-machine rig with Haiku sessions, running each promise exactly as the verification design states it.
  • Merging: both PRs green, an independent review, a version bump, then merged together and released. Nobody restarts your production Router.

Risks

  • Losing or doubling work at the migration, receive and confirm boundaries. This is the Advisor's top risk, so those three tests must pass on the real paths before anything is called working.
  • The public repo: the old design branch's history is never pushed; only the hand-picked docs are.
  • Turso migrations (the messages store) are tested on Turso temporary databases.
