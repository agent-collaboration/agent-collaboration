What happened

The design and plan were approved (31 October)

Four design documents, then the delivery plan. You approved it as written, adding that every milestone must be verified. Five lanes started on Sunclaw: central core, the receiving Router, notifications, republishing the design, and a Verifier.

PR 1 finished: database retention and approval state

Retention, WAL and vacuum on every database. Approval routes moved from approval-routes.json into a table, and the history JSON code was deleted. The first acceptance was withdrawn when the module-cycle check failed; after the placement fix, the Verifier re-checked it and M0 was accepted.

Central was built and accepted: M1, M2, then remote create and handover

Every central piece was checked on both runtimes, native and the real Cloudflare worker, plus wrong builds. Several gaps surfaced while building and were settled on the way. The Program Design now records each decision (see below).

The receiving Router's custody (S5) and command cutover (S6) merged

Full gates: central tests 1,162 passed, and the Host tests passed apart from six enrollment tests that fail only under the sandbox. Run outside the sandbox, those six passed 6/0.

The two-machine runs caught a real bug: cross-machine Wake send

The real CLI on A refused a Wake addressed to B before ever sending it, and reported the refusal as "outcome unknown". Fixed: a test that drives the real compiled CLI from A to B failed before the fix and passes after it.

The strict MCP run caught a Wake-wait deadline race

A local Wake wait could return "wait unavailable", because an outer deadline fired before the wait's own. Fixed with two phases in a row: the existing bounded owner selection first, then the owner's own wait. The existing "never guess the owner" test still passes.

Found: native create could hide a session it had already made

This bug predates PR 2. If the model or folder check failed after the native thread had started, or the approval route failed to register, the session existed but was recorded as "not submitted". The fix records the session the moment its ID appears, and reports it as created with the settings actually applied. Its tests failed before the fix and pass after it (3/0); the remote-create integration is still being built.

Twice, Sunclaw's disk ran low

The first time, another Lead's TUI build reached about 104 GiB, and free space fell to 2.2 GiB. The second time, growth from several worktrees took free space to 42 GiB. Both times builds stopped at the 42 GiB floor, finished build folders were cleaned with the evidence kept, and free space came back above 100 GiB. No data was lost, and production was never touched.

The test setup was pointed at your main Codex login. It was caught before any model call

Its launcher sent model calls straight to OpenAI on ~/.codex. It failed on an expired token, so no call was made. Your rule now lives in AGENTS.md, my memory, and every helper's instructions: test sessions use Luna through a debug Router, Haiku only with your approval, and never your main accounts or production. A sweep fixed 21 older test drivers that broke the rule.

Decisions I made, and why

These came up while building. Each is reversible, or is a design detail inside what you approved, so I decided it and recorded it in the Program Design. Anything that touches stored data is on Your decisions instead.

DecisionWhy
The interactions crate split is a separate PR (PR 2b), after PR 2You moved it. PR 1 got only a small placement fix. The PR 2b plan keeps one database, one migration set, and one direction of dependency
Prepare runs on the Schedule's target machine and binds through one new central callThe native thread is created there; central only records the binding
Portable import is one atomic central call; export reads from centralTwo separate creates would change IDs and lose atomicity. Off-grid times are refused, never rounded (your rule)
A Wake or Schedule is served from wherever its stored row lives (local until it moves, then central)Before handover, local definitions must stay readable and controllable. There's no fallback when central is down
The handover payload travels as the exact frozen bytes, and central computes the digest itselfAny retry sends the same bytes, and central never trusts a digest the caller sends
A carried Wake gets a Firing ID from the Router, which central records as already receivedSo central never sends work again that the machine already owns
Central's alarm also wakes for a carried Run owed in the futureOtherwise a Run already owed on a suspended Schedule would never fire
The old remote-Wake path is retired; retrying an old operation recovers its recorded answer, read-onlyNo double send at upgrade. This interim recovery gets deleted after its 32-day retention
Remote create keeps the public ACP wire unchanged. A private adapter takes only the request central has verifiedA new public field could be spoofed
The first input keeps the creator's verified origin exactly. A Router-authored first input is refusedIt's never relabelled as an unverified owner, and the public guards stay unchanged
The interim approver lives in a read-only remote-create.json that you edit by handIt follows the ports.json precedent, and goes away with PR 3's routed approvals
The handover freeze depends on enrollment, not on whether central is reachableAn unenrolled Router keeps its local automations running. An enrolled one freezes even when central is down
One debug test clock, shared by notifications and the automation timersTwo clocks would drift and make the tests lie
The alarm budget is fixed, not raised. The automation work is skipped only when there's nothing at allYou've said not to raise budgets; nothing owed can be hidden
Each kill test runs in its own fresh state folderOne run picked up a previous run's recovery. Isolating them is simpler and safer than a new control
