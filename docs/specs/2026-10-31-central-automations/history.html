How we got here

From the Advisor's read of this Mac's transcripts, ledgers and git history.

You asked where automations live

"what about automation? is that a global thing? is that a local thing? … where they live?" The Lead proposed definitions "global: on the fabric … one owner, one clock", but left the timer location open (D2). It was never closed, and the automation lane (P4) was never built.

A Lead added "a project's wakes and schedules pause" to your lease rule

Your words were about 4-hour leases. The pause clause was the Lead's own, marked as authorized. The same Lead admitted it on 18–19 Oct.

You asked "did we not put wakes and automations in central not in a project?" and removed the project link

The Advisor answered yes, wrongly adding that a project controls firing. You said automation "should not be associated with anything, should always work". Commit b8e63fedf (U80) recorded it on the local design branch only.

The published copy was the old one

On 22 Oct a reviewer noticed the docs in the published tree were "an older copy", and it wasn't fixed. On 25 Oct, #160 put exactly the pre-U80 requirements onto main, where they still are.

Only the cross-machine wake slice was built

Remote wake creation and controls (the B3r slice) shipped. They give each target machine its own timer, not a central list.

Much of the code already follows your later decisions: central-first project creation, no offline writes, and the removed lost-write family. It's the published documents that contradict it. So the docs fix is mostly about the documents, not about code.
