1. Who approves a session created on another machine

An agent on machine A asks central to create a session on machine B. The new session runs on B, and when it hits a permission prompt (run this command, write that file) someone has to answer. That someone is the session's approver. The question is who it is when the request doesn't name one.

What the code does today

  • Codex wants sessions, not people. A Codex create refuses a human creator or approver: "Human creators and Approvers are supported for provider endpoints only" (crates/collaboration-client/src/conversation_create_actor.rs:54–70).
  • The local default is the creator. When no approver is named, Codex uses the creating session (crates/collaboration-client/src/conversation_client.rs:501). Claude and Cursor endpoints also accept you as approver.
  • Prompts don't cross machines. Cross-machine approvals were deferred in board design U63, so a prompt on B can't be answered from A today.
