Fixing the published design

The board design on main is the version from before your 19 Oct decisions. The current version sits on a local branch that was never pushed: its history contains a Cloudflare CLI cache file with account metadata and an email. We publish the right documents without that history, as a hand-picked docs change in this stack.

Why not copy the branch

  • Its history carries the cache file, so pushing it would publish that file.
  • Copying its whole docs/ would delete newer docs that are only on main: the TUI, quota-dialog and crate DAG sets.
  • The branch itself still has two stale spots: PD2's "activity gate", and an explainer page showing the old U38.

Steps

Inventory every decision

Each statement on the branch is labelled: owner-settled, Lead realization, superseded, open, or planned-but-unbuilt. This includes U38/U80, the removed lost-write family, central-first project creation, interaction ownership and remote wakes.

Apply only the approved files onto this stack

A docs-only commit with no branch history. The two stale spots get fixed. Newer main docs stay byte-identical, checked against a file manifest.

Public-safety scan

On the exact staged files and the outgoing commits: cache folders, secrets, account IDs and emails, real staging hosts, Access identifiers, live service, session or machine IDs, and local paths. It also checks that no commit has the old branch as an ancestor.

Independent review, then it ships with the stack

Checked against your decisions and today's code. The docs claim nothing as built that isn't.

The Advisor read the code paths: central-first project creation, no offline writes, and the removed lost-write family are already as you decided. This fix is mainly the documents.
