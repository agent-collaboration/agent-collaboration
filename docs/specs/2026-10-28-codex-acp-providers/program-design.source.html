Model information: keep every model and use its actual controls

The owner chose to keep all model choices and requested research into the providers' ACP extensions. Use each model's actual controls when available. Otherwise the existing picker offers Use provider settings: select the model and leave effort to the provider. Never invent medium, infer a successful reset from missing metadata, or hide a working model.

This corrects structural How under U3–U5 and R3–R5. The unchanged Codex CLI uses its existing model/list and setting/input operations. The server-defined Provider choice is data in that existing contract. It is a bridge action, not a claimed numeric provider default.

Where the current information is lost

The Cursor handshake is already enabled. The existing executor reads actual config IDs, applies model before effort, and checks the returned current value. The Host/native catalogue loses those details and currently emits an empty effort list and hardcoded medium. Codex subsequently sends that medium as a real setting.

Cursor's existing cursor/list_available_models returns each model's own config options without selecting models. Its descriptor currentValue is a vendor-default choice; live session currentValue can instead reflect saved settings. Claude's legacy default is an actual SDK model-default reset. Claude's separate recommendedValue extension changes settings on creation/switch and is not a neutral read of an automatic default. This correction keeps the current negotiation.

The decoder consumes the matching source value and returns Unknown(reason) | Available { per_model_descriptors }. Missing budget skips the read. Failure leaves descriptors Unknown and preserves model delegation and session model choices. Represent actions without inventing facts

Native projection uses upstream's existing extensible effort string. For Unknown controls it emits the server-owned provider choice, described as Use provider settings, as default. For qualified Select controls it emits actual offered values and the actual provider default/reset value. It never copies the current model's choices across other rows. If an actual advertised value collides with the reserved action, mark the effort projection ambiguous and retain that model through ProviderSettings; do not guess which action the value means.

The native decoder converts provider to ProviderSettings and sends no effort setting. Sparse omitted/null effort continues to preserve state. A complete mask with null effort uses the selected model's available default action: ProviderSettings when unknown, or its qualified real provider value when known. It never treats Unknown as a reset success. All reported current effort comes from actual SettingsChanged state; the bridge action is not stored as an effective provider value.

Validate the advertised action before effects. A dedicated thread/settings/update that explicitly selects a ProviderSettings model row cannot apply a non-provider effort value: that row advertises only the provider action. Refuse the whole request with the existing Unsupported error (-32000) before any model or effort write. Never silently drop a complete mask's value or acknowledge a refused write. Qualified Select rows, sparse effort-only writes and the existing create/resume/TurnContext fresh-value rules retain their contracts.

Stock Codex primary Enter first sends the new model with the previous model's effort in a complete mask, then sends the chosen effort in a second request. For an Unknown-effort row, the first request therefore shows Failed to update thread settings; the following provider-action request selects the model without pinning that inherited effort. This visible refusal is the cost of preserving the provider's settings without guessing caller intent. Keep complete-mask precedence and use -32000: method-not-found, or invalid-request with the method name, would make this client permanently stop sending later settings requests. No coalescing, rollback or new client protocol is introduced. A controlled two-request countercase must prove zero effects from the refused first request and preservation of the target's saved effort through the next prompt; the real TUI observes the refusal and final effective selection.

Stop implicit replays inside the existing actor

Carry ExplicitChange | TurnContext through the existing internal SetSessionSettingCommand and runtime setter. Dedicated settings RPCs and other dedicated setting callers use ExplicitChange. Native turn/start context uses TurnContext. External wire DTOs and stored formats do not change, and every internal caller is updated together.

The addressed actor serializes the check with the effect. For TurnContext, any existing unresolved setting refuses before any model/effort write or prompt. When that provider's confirmation is eligible for reuse and the requested value equals the actor's confirmed current value, return the current result without an ACP write, new event or clearing uncertainty. A different healthy value, or a confirmation that is not reusable, retains the existing model-before-effort application and fresh choice validation. This preserves actual turn overrides while skipping only justified unchanged writes.

Confirmation must be reusable for this provider and setting. The immutable behavior trait declares can_reuse_setting_confirmation(ProviderSettingKind) -> bool. The equality shortcut also requires that predicate. Qualified Claude's setters act on the addressed query, so its session confirmation is eligible. Unqualified custom launches and Standard behavior conservatively do not reuse it. Cursor mode is session-local, but Cursor model and parameter setters use a shared modelManager and synchronize every session without broadcasting current options to each one. A different session can therefore make this actor's cache stale. Cursor model/effort retain their baseline per-turn reassert instead of using the shortcut; the unresolved barrier still comes first.

This is a qualification of the existing no-op guard, not a new global settings owner. No connection-wide cache, epoch, lock or process is added. The expected-model guard checks the actor's latest confirmed state and cannot promise provider-global compare-and-set or cross-session setting/prompt atomicity. Those preexisting Cursor shared-state limits remain explicit. A controlled two-session peer must reject the stale-equality skip while the session-scoped positive case still proves the optimization.

ExplicitChange retains the real setter even when the displayed value matches: choosing a provider default can be an actual reset operation, and selecting a level can intentionally pin it. Only its confirmed success clears that setting's existing unresolved mark. It cannot clear another unresolved setting. A failed/unknown reset is never re-dispatched by a later turn's mask; the existing prompt admission guard still blocks dependent input. ProviderSettings performs no effort write and clears no unresolved state.

When an effort action follows a selected model, the existing internal setting command also carries that expected model ID. The actor compares it with its fresh confirmed model before the effort write. A concurrent model change returns a typed context-changed refusal; it cannot redirect the effort to another model. A caller intentionally addressing the current model without an override supplies no expected-model precondition. This uses the same actor queue and adds no compound-operation controller.

A later effort failure preserves an earlier confirmed model change. Existing failed, unsupported, busy and uncertain results remain distinct. No rollback, auto-retry, recovery controller or new sender is introduced.

The expected-model guard's new closed native failure is -32602 with data.kind="settings_context_changed". An existing unresolved context uses -32000 with data.kind="settings_unresolved". Both preserve the request ID and report refusal before the guarded write or prompt. Existing native outcome codes otherwise stay unchanged.

Why this structure is enough

Use the existing catalogue and actor, with a small injected read adapter and typed action/intent fields. Maintainers pay for one Cursor read, a metadata payload, connection-local scope and propagation of setting intent. Users retain model choices and their provider preferences. Hiding models was rejected by the owner. Inventing a numeric default or using missing metadata as reset confirmation fails correctness. A second catalogue service, client fork and new SDK reset writer are unnecessary.

Revisit this mapping when a provider publishes richer typed defaults or the native client gains an optional default field. Until then, a labelled delegation action keeps an unknown fact distinct from an available operation.

Qualified parameter contract

The private binding shape is {baseUrl: string, localToken: string}: a nonempty absolute HTTP(S) URL and the unchanged nonempty opaque Host token. Capture failure is a bounded startup failure, not native/direct routing. The preparation result is Prepared(params) | Unsupported(reason), with reasons MalformedMetadata | UnsupportedSdkOptions. Unsupported returns before the original delegate and carries no input values or secrets. No new native error contract is introduced; the existing provider failure boundary owns its wire translation.

The injected preparation policy stays entirely in Claude-specific code. The shared Rust ProviderBehavior remains immutable and performs no I/O; the native facade, actor, session store and DI contracts do not gain credential or SDK logic. Reuse the existing lifecycle adaptation with one explicit preparation dependency rather than stacking wrappers or adding a general middleware system.

The private lifecycle dependency carries prepare(params): Prepared(params) | Unsupported(reason) and runCreation(operation): Promise<result>. The model module declares the narrow consumed shape; the entrypoint injects the prepared-file policy and its creation barrier together. For new/load/resume, enter runCreation before preparation and the original delegate, then settle it in all success/error paths; the ordinary setter bypasses this creation dependency. The file owner's beginShutdown(): Promise<void> synchronously closes admission and resolves when entered creations settle; its releaseAfterDisposal(): Promise<void> waits for matched children and removes its owned resources only after the caller has successfully awaited vendor disposal. No generic lifecycle registry or DI container is introduced.

The captured URL and real local token take precedence over ordinary routing fields at the SDK option boundary. Keep Anthropic selected and prevent conflicting native credential/backend carriers from restoring another route, using the inspected qualified provider semantics. Never substitute the vendor's acp-proxy placeholder for the actual local token. Preserve unrelated metadata, SDK preferences, cwd, MCP setup, permission handling, normal home and normal settings sources.

Temporary settings lifetime and failures

Validate the entire request and serialize its prepared settings before allocating a directory or invoking the original lifecycle method. Reject the qualified SDK's separate options.sandbox shape before I/O: at this pin it cannot combine with a settings path. Caller settings paths remain unsupported; the wrapper never reads or flattens them. The existing Host does not invoke ACP provider/gateway overrides, which would convert a settings path back into token-bearing inline JSON. A newly introduced actual consumer of those modes returns to this design.

The entrypoint constructs one focused file owner and injects its writer into route preparation. Subscribe to the process notification no later than directory allocation and before exposing any settings path to a delegate. On first valid creation use an OS temporary directory with an owner-only mode0700 and a non-secret name. Each creation writes a new exclusive immutable file, mode0600, before delegating once. No filename contains the token or user input. Track every allocated file before exposing its path; no overwrites or cross-session reuse. Keep successful and delegate-rejected creation files until wrapper shutdown, because a rejected vendor call does not establish that a partially created query has stopped using its settings. The file owner is derived resource bookkeeping, not a second conversation or settings authority.

Serialization or file creation failure rejects before delegation with a bounded error and no raw data. Remove any exact partial file when safe; if cleanup fails, keep it tracked for shutdown and report the bounded failure. A shutdown barrier prevents new wrapper-entered allocation and delegation. The existing lifecycle adaptation tracks its entered creation promises; shutdown drains those calls before vendor disposal snapshots registered sessions. This covers wrapper-entered new/load/resume only. Vendor-internal clear-context or sign-out recreation can still race disposal; it reuses the same path, and a recreation after release fails closed at ACP's required settings-file read. No new internal recreation drain is introduced or guaranteed.

Vendor disposal is not child exit. ACP0.81 calls the SDK's void query.close(); its asynchronous cleanup can continue after dispose() resolves. The file owner therefore observes the existing default Node spawn through the documented diagnostics_channel child_process notification. Attach a once-only close listener to the supplied actual ChildProcess immediately; after the synchronous spawn finishes, inspect its public spawnargs in a microtask for the exact --settings followed by an owned path. Retain only matching handles and their closure promises; remove the listener for an unrelated child. Remember an already-fired close across classification. Do not retain or log arguments, environment, PID or unrelated process data.

Track every matching successfully spawned child, including multiple recreations using one path, and every pending classification before treating the consumer set as empty. Use the raw close event, not an error-rejecting generic event promise: an error alone is not cessation. At classification, the public ChildProcess pid being undefined means spawn created no process; remove that object's close listener and do not await a nonexistent child. A defined pid means a process was spawned and its actual close is required, even if it already closed before classification. This is a boolean check of the supplied handle, not PID polling or a retained identity. Cover both synchronous failed spawn and asynchronous missing-executable failure. The legacy channel preserves the existing Node22+ qualification range; newer tracing channels are not assumed available throughout that range. The witness covers those direct children and their pipes, not arbitrary descendants. Exact runtime behavior remains a qualification obligation.

Reuse the existing idempotent EOF/SIGINT/SIGTERM shutdown: stop admission, drain entered creations, await the vendor's disposal, flush pending child classifications, and await closure of every matched file consumer, including a failed unregistered query. Keep the subscriber active until no entered creation or matched consumer can introduce a later file use. Then unlink only tracked files, remove the now-empty owned directory and unsubscribe. This observation does not replace spawn, consume SDK output, read a second iterator, send a signal or poll process identity; SDK spawning/debug/stderr behavior remains vendor-owned. A creation that reused an existing query may leave an unused file, also retained until this shutdown boundary.

Never recursively delete a caller path. Disposal rejection or an unclosed successfully spawned child retains the files; neither is successful cleanup, and no timeout is converted into success. Disposal, child-observation or file-cleanup failure emits only a categorical stderr line Qualified Claude cleanup failed: VendorDisposal | ChildObservation | SettingsCleanup and exits nonzero when it can settle; never print a raw vendor error. Permanent entry tests observe that result. The current Host's retirement path kills immediately and does not earn this cleanup claim; its correction and failure propagation depend on the separate retirement decision above. Node's built-in process notifications are documented but experimental: qualify the exact runtime through a permanent real-child case and name other runtimes unverified. No global store, scavenger, secure-erasure promise or private SDK hook is added.

Parameter preparation remains separate from the model decorator: model facts stay result-only and independent of skill facts. All delegates retain their receiver and execute exactly once. There is no query.next interception, extra SDK query/consumer, public field reset, model/effort pin writer, new provider process, user configuration edit, retry or operation reconciliation.

Policy, failure and alternatives

Managed policy remains authoritative; this correction does not promote route settings into managedSettings or bypass a policy helper. The public resolver does not execute policyHelper, so it cannot prove that helper's eventual effect. A demonstrated policy conflict or unsupported actual caller contract stops dependent work and returns its evidence; no alternate endpoint is silently selected or accepted. No such actual conflict has been established by source inspection.

Environment-only routing leaves the displacement path open. Inline SDK settings expose the token in native argv and SDK debug formatting; a later custom-spawn hook cannot undo that. The existing providers/set API supplies a placeholder bearer. The selected public settings path retains the existing vendor query and moves the accepted cost to private file lifetime and cleanup. Revisit it when the qualified vendor API can preserve the real Router bearer without a file or token-bearing arguments.
