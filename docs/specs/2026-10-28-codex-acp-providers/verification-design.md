# Verification Design: TypeScript TUI journeys and meaningful regressions

Use the existing **`scripts/verification/tui` TypeScript verifier** to drive the real Codex CLI. Its native adapter owns the PTY; TypeScript owns declared-target qualification, scenarios, readback and original-artifact checks. Supporting API observations confirm provider effect and identity. They do not replace driving the TUI.

This defines proof obligations and makes no qualification claim. Actual run status lives in the project verification recipe and retained evidence. Inputs: [Requirements](requirements.html), [Specification](specification.html), [Program Design](program-design.html).

## Existing harness and needed extension

The package currently supports **Quota and Sessions**. `capture-run.ts` exposes those surfaces; `public-sessions-run.ts` drives the public Sessions entry. Add an installed-Codex ACP target/scenario in this package. Do not run an existing Quota/Sessions capture and relabel it Codex proof.

| Existing source to reuse | What it establishes | Needed Codex extension |
| --- | --- | --- |
| `source-binding.ts`, `evidence-schema.ts` | Exact source/executable/tool binding; current harness requires Node26.12.1 | Bind installed Codex, candidate Host/router, native adapter, private socket, provider/session/cwd and viewport using the existing artifact/schema patterns |
| `driver-lifecycle.ts`, `public-lifecycle.ts` | Exact driver discovery, bounded launch/settlement, cooperative owned cleanup | Launch unchanged Codex through its real `--remote` session entry; no production replacement/config writes |
| `cua-readback.ts`, `original-artifacts.ts` | Same-child/PTY identity and original capture/readback checks | Actual Codex keyboard scenarios and checkpoints, preserving original PTY/captures and matching native requests |
| `scene-contracts.ts`, `capture-selection.ts` | Explicit scenes and accepted input/selection | Bounded Codex ACP scenario and checkpoint oracle; no generic second capture framework |
| Shared `TerminalDriver` in `crates/codex-router-quota-reset-test-harness/tests/quota_reset_pty_test/terminal_interaction_test.rs` | Existing Rust PTY owner; shared backend supplies streaming reads, explicit-environment launch, keys, resize and exact-child cleanup | Keep Codex journeys in this harness crate and use its shared TS wterm bridge; no second PTY/renderer or generic support crate |
| `verification/observations/acp-metadata-observation.ts` | Public target/session/native API/history readback | Supporting skill/command effect observation correlated with that same TUI child/session; it remains an observer, not the TUI driver |

The extension is **needed**, not an existing option claimed to work. Actual keyboard selection, submitted native input, original artifacts and provider result must refer to the same declared child/session. Receipts alone establish neither visible UI nor a provider effect. Keep existing Quota/Sessions scenarios and rejection tests intact.

### Shared capture backend

Use the TS/Rust backend shared with the TUI component work: Rust TerminalDriver owns the unchanged installed Codex child; its output feeds the TS `@wterm/core`/`@wterm/ghostty` cell grid. Mechanical checkpoints assert on that grid. Original PNGs come from `@wterm/dom` rendering the **same exact PTY bytes**, bound to source/build/viewport/checkpoint and unchanged child identity. A picture reconstructed from cell data is diagnostic only. Qualify the shared engine on known colour/wide-glyph/query/resize fixtures before relying on it. Answer terminal queries from the emulator state; retain keyboard mode, raw offsets and checkpoint order.

The common backend has one owner in the TUI workstream. Its pushed implementation and qualification are dependencies, **not code or proof claimed to exist on this branch**. Codex adds a guarded launch/scenario, grid predicates and same-session supporting observer. Preserve normal Codex home/trust/config, declared program/args/environment, session/endpoint/socket/cwd, original artifacts and owned cleanup. Real J1/J2/J3 wait for this shared driver and the candidate; no controlled stand-in closes them. Do not add VHS, ttyd, xterm.js, Swift or shell proof machinery, and do not duplicate the backend to avoid that dependency.

## What you will see

### U1 — Both providers' real skills appear

The TS/native-PTY journey opens `$` against Claude and Cursor, sees the expected fixture skill and excludes a command. Late metadata updates without a stalled client; errors are visible beside valid rows. An unqualified original Claude launch shows SourceUnavailable while chat/settings remain usable; it does not count as the required qualified Claude success. **Unverified until run:** new Codex scenes, actual rendering and real provider classification.

### U2 — Keyboard-selected skills actually execute

Select through the real picker, submit distinct arguments and an image, and observe a provider-owned effect absent from the literal prompt. Include leading/nonleading input and multiple distinct Cursor skills. **Unverified until run:** native expansion, path round-trip, preserved content and actual error presentation.

### U3 — Existing slash operations have their distinct effects

Drive `/model`, mode and `/compact` in the same TUI. Read effective settings and Claude's compaction marker plus terminal outcome. Cursor compact shows unsupported and leaves input usable. **Unverified until run:** real command flows, effects and busy/error handling.

For an Unknown-effort model, exercise the stock primary-Enter sequence from a different model with numeric effort. The initial model/settings request carries that old effort and must receive the existing Unsupported error before any provider write; the later provider-action request remains supported. The TUI must show the first setting refusal, retain the final selected model, and permit the next prompt. A permanent controlled Host/ACP case uses distinct saved efforts for the two models and decides zero writes from the first refusal, no numeric effort write from the provider action, and the target's saved effort after the prompt. Final native/provider current-value agreement alone cannot prove that its preference was preserved: a wrong build could overwrite both to the same inherited value. This strengthens the existing J2 setting/refusal seam; it adds no observation framework or provider-discovery model switches.

### U4 — Conversations and their lifecycle survive

Drive live/reopened chat, interrupt and approval controls for both providers. Read back the admitted single-Text skill message as the exact original `$name` input, including Claude nonleading input that prepares into two Text blocks; keep main's no-synthesized-item behavior for image/multi-block input and separate provider user-group IDs. Refresh skills during an active turn while retaining its stream, identity and terminal result. Keep separate native Codex/reverse ACP controls. **Unverified until run:** actual interleaving, history and owned-process cleanup.

### U5 — Constructor DI supplies the right implementation

Run the real consumer with differing implementations of the same ProviderBehavior trait and observe different literal classified/prepared results. Native codec tests reject foreign endpoint/session or mismatched name/path before typed selection; actor tests revalidate invocation against its current addressed view after queue wait. Inspect constructor propagation, dependencies and shipped asset. Force qualified and unqualified Claude launch preparation; verify the exact resulting executable/arguments, preserved environment and immutable constructor input, plus source error and unsupported compact for the unqualified case. **Unverified until implementation:** both session-admission paths, session-state isolation and final normal-build graph.

The Host's selected route is judged against its existing URL/local-token binding, not against the provider's CLI-login status or OpenAI model-list traffic.

Retain every existing U1–U5 row and J1/J2/J3/native/reverse obligation. The ordinary control is diagnostic isolation, not a substitute for a required selected-skill/image interaction. Capture exact source/artifact/configuration/Session bindings and original wterm bytes. A reply through an unrelated credential is insufficient to establish the selected Host route.

**Required real Claude route window.** Reuse the normal debug Host's existing `<run_directory>/router-audit.jsonl`; no product logging or new audit field is added. A small TypeScript consumer in the existing `verification/observations` package is needed. It binds the file to the declared Host/run directory. A fixed hook in the existing TS Codex journey runner records file identity, byte length and prefix digest after the composed-input checkpoint/original capture and immediately before the submission Enter; it is admitted only for the declared Claude prompt/skill route-proof plans. It is not an arbitrary callback or another driver. Model setup/readbacks must already be idle. A permanent shared-driver countercase must reject capturing the baseline before composition or after Enter. After the reply and its same-session completion readback, it validates the unchanged prefix/identity and reads only the bounded appended segment. It retains categorical fields and counts plus `accountHashPresent`, never raw account hashes, request IDs, headers, bodies or arbitrary audit text.

The audit file is created lazily by its first decision. If it is absent before Enter, record `file.state=absent` explicitly and treat the bounded file created afterward as the whole window. If present, record identity/length/prefix and require continuity. Absence after the reply still fails; an absent baseline never waives a positive forwarded row or the genuine reply.

Pass only when that segment has at least one `claude_messages / http / valid / allowed / forwarded / committed` row with an account hash present, and no rejected Claude row. Ignore models/responses traffic. Missing after-reply, malformed, rotated, truncated or over-bound evidence, no allowed Claude HTTP row or a rejected Claude row fails route qualification; it never triggers a prompt retry or claims an auth cause. Permanent reader tests must reject those countercases, a WebSocket-only Claude row and a models-only segment. The same finite prefix/segment caps apply to both authored run input and decoded baseline records.

The target window requires one private normal Host, one fresh Claude Session and an unshared declared listener. Observe the managed-Session precondition through the existing `provider_sessions_list` operation: `view=stored`, `source=all`, `scope=any`, page size 100, no query and no cursor. Use the normal build's bound collaboration CLI. Read once at the fixed composed-input hook before recording the audit baseline and sending Enter, and once after the completed same-session reply readback. Each read must return exactly the declared hosted Claude Session, idle, on the declared service; require one complete page with no cursor, native coverage or skipped records. Any other managed Session, including a closed or unloaded one, invalidates attribution. Errors, unavailability, wrong identity or incomplete inventory fail without retry. Retain only the service/Session identity, state, count and observation time; do not retain actor or policy fields. Permanent countercases must reject a forwarded row paired with a genuine target reply when either inventory contains another Session.

Use the existing retained `thread/read` before-state to reject an additional turn in that same Session. Bind it to the declared native alias and cwd and require it idle; both final native views must preserve its turn prefix and add exactly one completed turn, the turn already established by the ordinary-reply or selected-skill check. An intervening completed turn or changed prefix fails even if the final reply and audit row would otherwise pass. This reuses history observation; it creates no product reader or correlation field.

The existing audit has no Session/timestamp join and its request ID is constant; attribution therefore rests on this isolated causal window, not an exact prompt join. The inventory observes managed Sessions, not an unrelated native Claude launch using the same debug listener/token. Keeping that private listener unshared, with no native Claude launch or other generation input against it, remains an explicit allocation premise. Unexpected background/other-Claude traffic invalidates attribution. An allowed committed row is written for a forwarded response head even on an upstream error: it proves neither HTTP success nor stream completion. A valid-token request failing selection can produce no row; absence alone cannot diagnose displacement. The genuine provider/native reply and normal CLI exit remain mandatory, alongside the route window. Do not add a new reader, query or correlation field to product code to hide these limits.

The permanent creation-boundary cases also set `CLAUDE_MODEL_CONFIG` with distinct literal `availableModels` and `modelOverrides`. When the caller supplies no settings, both must reach the SDK alongside the protected Host env; caller-provided inline settings retain the vendor's existing nullish precedence instead. Include missing/empty config and malformed/non-object/array failure cases; even an explicit caller settings object must not mask the original vendor validation. A route-only settings object that silently removes the model catalogue or aliases must fail even if the URL/token assertions pass. The runtime model catalogue remains provider-owned; the test does not manufacture or select discovery models.

Candidate: clean committed source containing current main; isolated normal signed debug Host on macOS; unchanged installed Codex0.165.0; Claude ACP0.81.0/SDK0.3.280 and qualified native Claude; Cursor2026.10.22-27dcf5f. Requalify updated providers/tools before extending a claim. Use private unused root/socket/port and normal trusted Codex home. Preserve production/config. Exact toolchain/capacity is a delivery-preflight input, not an assumed pass.

- **J1 skills — needed, lasting:** extend `verify-codex-router` with TS-driven actual `$` selection/input and same-child captures/readback for both providers. Supporting native input/list and provider effect distinguish execution from echo. Include empty/late/failed metadata, cwd/session isolation, ambiguity, full-token arguments/images and multiple Cursor selections.

Supporting public history keeps genuine prose, user input and metadata distinct. Native Codex/reverse ACP controls stay separate.

## Tests that can catch the wrong implementation

Take expected values from C1–C3/native schemas or checked producer fixtures, not production helpers. Keep the smallest responsible boundary real.

| Wrong behavior | Valuable regression / independent oracle |
| --- | --- |
| Picker and submitted identity differ | Actual TUI selection and native request match the fixture's identity and provider-owned effect. Native decoder rejects foreign endpoint/session and conflicting name/path; the existing target survives command/FIFO/admission. Domain/adapters carry invocation identity without a native path. Screenshot presence alone cannot pass. |
| Wrong behavior injected | Actual consumer receives two scripted trait implementations with different literal outputs; assert emitted value/wire content, not only a constructor or method call count. |
| Claude wrapper is never launched or qualification is ignored | Preparation tests qualify the checked official-bin/pnpm-shim fixture and reject custom/mismatched targets. Inspect actual rewritten launch/import identity; real original-launch integration yields source error, zero skill/compact prompts and working ordinary chat. J1 separately requires qualified real Claude success. |
| Cursor command looks like a skill | Literal producer rows retain distinct terminal command/skill indicators. Cover mimicking titles, exact nested IDs, duplicate/unknown/uninvocable rows and valid rows alongside errors. |
| Skill disappears during a queue wait | Hold dispatch, replace view, release; real ACP peer sees zero prompts and Host receives immediate refusal. No sleeps or timeout increases. |
| Content rewritten incorrectly | Table/property cases preserve independent literal Unicode, whitespace, suffixes and image payloads. J1 separately checks actual multiple-Cursor/single-Claude native expansion. |
| Claude reload loops or publishes after retirement | Controlled Query promises force echoes, descriptor/result changes and retired state/query; actual TS output enters real Rust decoder. J3 separately decides real turn preservation. |
| Compaction succeeds from an ack/title | Real codec/actor cases cover marker+terminal, missing/failed/automatic marker, cancel and uncertainty; only C3's combination succeeds. J2 proves real provider effect. |
| Verifier accepts false evidence | Extend existing rejection tests for wrong source/binary/provider/session/PTY, absent/reordered checkpoint, echo-only output and blank/wrong scene. Assert the real rejection. |

Pure rules use focused tests; DI/serialization/actor ordering uses real-consumer integration; actual interactions use the existing TS/native-PTY journeys. Do not repeat every parsing edge through the TUI. No temporary test files, hand-authored success receipts, terminal emulation or standalone replacement verifier.

If native expansion, Cursor output or active-turn reload contradicts the design, return the failure to Program Design. Do not drop a provider or count unavailable skills as U1 completion. The HTML document-preview limitation is separate from this product verification route; no product journey is reported passed here. Other versions/platforms and release proof remain outside the declared target until qualified.
