# Observable behavior

Reference: [Requirements](requirements.md), accepted set U1–U16 and its named preservation variants and later catalogue authorization. The boundary is Sessions/Quota presentation and interaction on a new branch from main, plus the explicitly authorized existing-provider actions and shared inventory projection. This document describes what a person can observe, not component ownership.

## Scenarios and obligations

People: P1 is the owner browsing/debugging sessions and quota across existing machines/providers. P2 is the maintainer adding another menu without reimplementing layout. Outcomes: O1 predictable interaction, O2 readable information, O3 preserved capabilities, O4 independently proven delivery.

All R rows are mandatory. Their target is the real compiled Sessions/Quota UI unless a row explicitly targets source/delivery artifacts. The reference is the corresponding U row plus the existing capability inventory, not the HTML implementation. V rows below name proof obligations, not test results.

## Constraints and reference inventory

C1 iocraft layouts and existing semantic palette; C2 unchanged domain/storage/transport/effect owners and uncertain outcomes; C3 no feature/proof removal; C4 no production replacement, model turn or paid call needed for UI proof; C5 current-head source and real compiled UI; C6 all preserved static/list/JSON/CLI modes continue to work. Existing command/provider capabilities are the limit: a searchable provider list does not authorize new provider launch support.

Reference inventory, base ffced1c1: Sessions request/model/component and command options/dispatch; Quota status, filter, account options/floor/reset models and controllers; shared DialogFrame/DialogHost/ShortcutHelp; current actual-TUI capture harness. [Program Design](program-design.md#current-system) links their decisive owners. The current picker source filter has no visible control; the redesign makes the already-defined option reachable in the shared filters. Checkout must keep its CLI semantics even if its presentation projection changes.

V1–V14 correspond one-to-one with R1–R14. The separate [Verification Design](verification-design.md) selects journeys and checks; these are planned observations, not observed results. This specification sets no invented performance number or arbitrary row limit. No open product-meaning decision is required for these contracts. A structural feasibility gap must be resolved in Program Design, not hidden by weakening a contract.


## Later owner correction: Claude background launch

R15 (U15): `agent-sessions --provider claude --new` invokes native Claude background mode without requiring the user to remember `--bg`. Existing Claude resume and fork launches also remain in background. The same launcher contract is used for TUI Claude actions. Forward supplied arguments unchanged after the required background default. The native Claude CLI owns its option grammar and rejects incompatible print/background modes before creating or dispatching a background session; propagate that actual failure without inventing success. Do not drop option values or duplicate the vendor parser. Existing model/effort/prompt/working-directory arguments and Router routing environment remain preserved. Successful dispatch means the CLI's actual background result and ID, not a foreground process left under shell `&`. ACP-hosted Claude is already a separately managed protocol session, not a terminal process; do not reinterpret its endpoint-owned ID as an interactive transcript ID.

R16 (U16): New has inline searchable Client and Machine fields in the same shared form. Codex uses its existing native route; Claude Code uses native background mode; Cursor uses the selected Host's existing managed ACP create route. Show truthful completion and actual returned identity on the selected machine. Managed provider Resume/Load uses its own endpoint-scoped ACP API and advertised capability; native Claude Resume/Fork uses its recorded native session identity and background CLI. A background job handle is separately labeled and never substituted for a native conversation UUID. Existing managed Claude records remain managed; no implicit conversion. Unsupported provider Fork stays visibly unavailable with its actual reason, never routed to Codex or fabricated as supported.

Selection, action target, directory and source identity are captured before an effect. A selected unavailable client/machine explains why; there is no local/default fallback. Each managed ACP mutation uses one caller-generated Router operation ID and the existing outcome/readback contract; an uncertain SSH/API outcome is surfaced, never automatically retried. Native Claude is an external CLI launch: preserve its actual observed receipt/status and captured source/action identity. Lost native output remains unknown, with no fabricated Router recovery ID, promised operation-show reconciliation or automatic second launch. Client-family filtering is separate from backend model-provider filtering. Human use of the TUI uses the existing selected-machine OS-owner identity for provider API attribution/approvals, not a fabricated agent SessionRef.

Native Claude inventory and managed-provider inventory retain distinct origins even when their visible IDs coincide. Loading stored and live provider views must preserve existing stored sessions and include live Claude background peers using actual typed summaries; names never infer origin/capability. No native Cursor terminal-ID equivalence is assumed or needed for managed ACP controls. Final acceptance requires actual selected-machine create/resume/load and truthful unsupported states for both clients through public agent-sessions plus the compiled UI, locally and remotely. This design does not add a chat composer or provider-native terminal attachment.


### U16 inventory availability correction

A valid managed Stored catalogue and native Claude live/Loaded inventory are independently available parts of the same source view. Successful Stored rows remain visible when the additional native-live read is unavailable; show an explicit partial-view notice identifying the missing native inventory, including when it returned no rows. Unavailable is not an empty successful inventory. Keep observed, origin-qualified rows and selected/action identity; do not infer that a missing live result deleted a session. A genuine successful empty live result remains distinct and complete. Wrong-service/binding, changed epoch, malformed pages, invalid cursors and duplicate same-origin identities retain existing rejection semantics; this correction does not turn invalid data into partial success.

### R16 shared native background catalogue

Both public Router inventory and Sessions expose native Claude background jobs before their first prompt, alongside existing native interactive peers and managed provider sessions. Starting new Claude sessions through agent-sessions always uses native background mode. Listing an existing interactive or managed session does not convert its origin or lifecycle.

A background job handle, native conversation UUID, peer process and managed SessionRef are different facts. Copy/Resume/Fork use the attributable native conversation UUID; the job handle is separately labeled. Never invent a peer PID/socket, updated time, managed policy or Router operation for a job-only observation. Unknown vendor state remains unknown and grants no additional action capability.

Native background history, including stopped jobs with a valid native conversation UUID, is available through native Stored inventory so an eligible session can be resumed after its worker stops. Existing managed Stored/All semantics remain; native Stored/Interactive adds vendor job history and does not promise historical peer transcripts. Native Loaded/Interactive includes live peers and active background jobs; native Active requires working/busy evidence, not mere existence. Interactive here distinguishes native owner sessions from Router-managed storage; background execution is not a subagent classification.

Peer, background and managed observations remain independently attributable. A known unavailable additional native source produces explicit incomplete coverage while preserving other qualified rows. Malformed, wrong-source, stale or ambiguous identities remain invalid, never successful-empty. A matching native UUID corroborated by a job and peer represents one native Session with its available observations; equal managed/native UUID text still represents different sessions. Creation, discovery, revalidation and action must compose through each actual selected-machine debug Router in final local/remote proof, without a model prompt.
