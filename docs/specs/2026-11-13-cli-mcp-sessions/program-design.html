Steer by restart

Retry storage: provider_operations holds status only. A repeated requestId returns that status and the result while it is still in memory; otherwise outputUnavailable. No answer column is added.

Sends to one session run one at a time, in arrival order. Turn T is read when a send starts executing, not when it arrives, so a second steer that waited behind a restart sees the new turn T1. A prompt that returns Uncertain ends the request unknown (never retried automatically; reconcile settles it).

Approvals: one record, many destinations

Central is the record of truth and the arbiter (owner decision D8). The Mac's broker keeps only the agent's waiting request in memory, sends RequestApproval to central, relays answers from attached clients and the parent to central, and applies the ApprovalDecision central delivers. If the Router restarts or the turn stops, the agent's waiting request is gone; the Mac tells central "requester gone". Central ends the approval cancelled if it is still pending, and keeps its ending if it already recorded one (a decision that arrives for a gone request changes nothing on the Mac). Central's recorded ending always wins. After a crash nothing is reported, so the recovery belongs to central (dependency named in A7): on reconnect the Router announces a new lifetime and central cancels whatever was still pending from the previous one. No local persistence is added. While central is unreachable, approvals wait (the agent is told it's pending). Central's side (table, arbitration, late-answer refusal) is the central Lead's deliverable D (A7); until it lands, a stand-in arbiter runs the same rules.

After an approval, Claude's retry of a classifier-blocked action gets through (or the acceptEdits switch makes it ask). Experiment E2 decides.

Clients anywhere: the Codex socket shows approvals

The Router's Codex app-server face turns a session's approval events into the Codex approval requests the Codex CLI already renders, and turns its answer into decide. Its typed protocol comes from the Protocol Lead's contract crate (L4).

Non-delegates: a Router setting

Every non-delegate's approvals go where settings.jsonc says: "approvals": { "nonDelegates": { "central": true, "attachedClients": true, "agent": null } } (the default), or with "agent": "<SessionRef>" to also send them to an agent you pick. A new setting key, not a stored-data change.
