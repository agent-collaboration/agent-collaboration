Program Design

The Router is a graph of twelve nodes. Each node is fixed in place: it decodes into typed messages, does one declared conversion with owned state, and emits typed messages. The types come from three definitions: a Rust crate generated from Codex's own export, the official ACP SDK, and one Router vocabulary, which Specta turns into TypeScript. Duplicate conversions collapse into the node that owns them. Every map here comes from the verified map of the code at c4b6254e1.

The graph today

Rose nodes convert with untyped JSON. Amber nodes are partly typed. N2 is a byte relay: a Codex CLI on a Codex session never passes through the shim (native_channel_relay.rs:10). N9 has no product client; only tests use it.

The graph after

Every edge the Router decodes is typed. N9 is kept and typed (D24). The shared middle is N4, N5 and N7, plus the three definitions.

How the types are made

Codex: our own TypeScript generator over the pinned export, with pairing taken from common.rs. It writes plain serde Rust, committed. t3code does the same in TypeScript/Effect, but pairs requests by naming plus a 12-entry hand map (generate.ts:491); we use Codex's own declaration. Rejected: Codex crates (C1); typify (it loses null versus absent, extra fields and pairing); hand types (U2). Would reopen: Codex publishing a small protocol crate with semver.

Override registry and open-enum rule. Every departure from the export lives in one registry, with its shape, reason, removal condition and a test. Fields whose values grow across releases decode an unknown value as Unknown(String). This is t3code's lesson: a closed CodexErrorInfo dropped turn/completed and left turns running (generate.ts:175).

Vocabulary to TypeScript with Specta (specta-typescript). Its Zod and JSON Schema exporters are experimental, and you found them flaky, so we don't use them. Hand-written Zod stays only where TypeScript parses foreign input (Claude SDK output), and keeps its refinements. It is tied to the generated type with satisfies z.ZodType<T>, so drift fails tsc.

Specta 2.0.0-rc.28 handles our serde attributes: flatten, tagged enums and Option<Option<T>>. A small experiment in D0 checks this before D6 relies on it. Depends on it: D22.

Pairing coverage: common.rs pairs all 179 client and 11 server requests in the export, and every response type it names exists. Three deprecated source-only requests are ignored. For future releases, the generator fails closed if this changes.

The ACP SDK types both roles, so it can be the one ACP authority.

For external enums that may grow (the ACP SDK), R9 is enforced by a required check against the pinned SDK's own schema, not by the compiler. A new ACP variant can only arrive through a deliberate version bump, and the check fails until every variant has an entry.

CI can install Codex at an exact release for the online drift check.

Typed extension messages

  • Steering: request and reply as above, with a 10 second timeout. The outcome is a closed enum; any other value is an invalid-reply error. A timeout or dropped channel is a transport failure. Injected while running keeps today's side effect: InputAccepted plus the user message. StartedNewTurn while idle is a change row: today it publishes TurnStarted, the user message, and at once TurnEnded with Lost { EndNotObservable } (provider_session_actor.rs:449-475), so the turn is reported lost while the agent is still answering, and its items then arrive after its end (breaks O5 k1). It is a current defect on D0's expected-failure list, fixed in D3: the started turn's end must become observable, or the outcome must not claim a turn; which one is an open design item D3 settles in its own design pass before its plan.
  • Cursor model discovery: 2 second timeout. Any failure means no model data is available. Unknown fields are allowed. The effort option is chosen as today (model_reasoning_metadata.rs:100-204).
  • Claude model reasoning (_meta.codexRouter.modelReasoning, version 1): either available models (model id, plus config id, choices and default) or unknown with a reason (UnsupportedSource, Unavailable, Malformed, Ambiguous, Unrecognized). The checks JSON Schema can't express stay in both Zod and Rust, tied to the one generated type (D22): the default must be one of the choices, choice values must be unique, and model ids must be unique. Two retained differences are named, not hidden: Zod strips unknown keys while Rust rejects them, and Zod pins version 1 while Rust reports other versions as Unrecognized.

The interfaces that enforce it

  • CodexCallError is closed: Transport, Rejected, MalformedResult { outcome: OutcomeUnknown | Protocol }. A malformed result retires the connection, as request_validated does today.
  • Raw JSON exists only inside the generated crate's codec.
  • Matches over our own types (generated Codex types, Router vocabulary) have no wildcard arm, so a new kind fails the build.
  • The ACP SDK's enums are #[non_exhaustive] (schema 1.9.1, SessionUpdate at client.rs:98), so a downstream match must have a fallback. There the fallback maps to a named Unlisted disposition, which is recorded and never dropped silently. A required check reads the SDK's schema at the pinned version (=2.2.0, via its schemars feature) and fails if any variant lacks an explicit entry in the node's disposition table (D25).

Following a Codex release

The offline check, part of the required checks, verifies the header hashes and regenerates from the committed export. The online check installs the pinned Codex and compares its export. Orca checks its ACP schema the same way (generate-protocol.mjs --check).
