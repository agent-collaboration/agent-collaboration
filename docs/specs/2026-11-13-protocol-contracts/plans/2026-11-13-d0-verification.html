Plan: D0 verification first

D0 builds the harness that every later deliverable is judged by, and changes no product behavior. It has five parts:

  • node taps;
  • Codex-vs-Router stream comparisons on the real Codex CLI;
  • a two-sided baseline: historical bugs fail before PR #242 and pass now, and current defects are recorded as strict expected failures;
  • a producer/consumer report;
  • deletion of seven uncompiled Host files.

It ships as one PR.

Gates, risks and stop conditions

  • Standing rules:
    • debug Router only, with Claude on Haiku;
    • no production Router, no production installs;
    • every Rust run goes through scripts/cargo_debug_signing_runner.sh;
    • one injected clock, no wall-clock tests;
    • no file over 1,000 lines;
    • no permanent repo-wide source scans (the send-site review is done once);
    • no git stash.
  • Risks:
    • Haiku quota on the debug account;
    • some node types are crate-private, so their taps must live in colocated tests;
    • building at 95ab03b56 uses disk, so that worktree is removed after the baseline;
    • Cursor stays unqualified (A31);
    • the journey driver may need more than an extension (A30).
  • Stop and come back to the Lead if:
    • a node can't be driven in-process without changing production structure (a program-design gap);
    • the structural comparison can't tell a correct Claude run from a wrong one (a verification-design gap);
    • Lead A refuses the codex-router-host changes;
    • any baseline case behaves differently from what the catalog says today's code does.
