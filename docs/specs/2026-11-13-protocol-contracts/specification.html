Specification

Every edge carries one protocol, whose types come from one definition. Every node declares what it does with each message kind it receives, and what comes out (zero, one or many messages). Any state a conversion needs is owned by one place. Every message's producers and consumers are listed. Verification proves each edge, each node and each stream against a real reference; for Codex, that reference is Codex itself.

Codex app-server contract

  1. R1 · Codex-protocol edges use contract shapes, or the build fails. This covers every message the Router decodes on an edge that carries the Codex protocol. The byte relay never decodes, so it is exempt. E2 E4 E5 · U1 U2 · V1; ref: the pinned release's export.
  2. R2 · Absent, null and set stay distinct, and each field keeps its own meaning. In 0.166.0, serviceTier: null clears the tier, but disabledPluginIds: null keeps the list. E4 · U1 U2 · V2; ref: the export's field docs.
  3. R3 · Each request is tied to its response, as Codex declares it at the release commit. A wrong pairing fails. E4 · U1 · V3; ref: common.rs at 6ff1e1ca (179 client + 11 server requests covered).
  4. R4 · Relayed unknown fields arrive unchanged. E4 · U1 · V4.
  5. R5 · A value Codex adds later never fails a whole message. Where a field's values grow across releases (error codes, plan types, hook names), an unknown value is kept as unknown. Messages that settle a turn are never dropped because of one. E4 · U1 U3 · V5; ref: t3code's CodexErrorInfo lesson (generate.ts:175).
  6. R6 · Departures from the contract go only through the override list. Each override has a reason and a removal condition, and is rechecked on every refresh. E9 · U2 U3 · V6.
  7. R7 · One refresh step makes the contract. Drift fails the required checks. A release change lists every shape added, removed or changed, and a broken build names the shape. E5 E8 · U2 U3 · V7.
  8. R8 · Another Codex release is named before any thread or turn starts. The Router runs the installed Codex only when it is the pinned release, and admits only tested CLI releases (D8). An opt-in Router setting, off by default, lets an untested CLI release connect. The mismatch is still named first, a warning stays visible on that connection, and any request shape the contract doesn't know gets a named error (D8). E8 · U3 · V8.

Every node fixed, one definition each

  1. R9 · Every inbound message kind at every node has one declared disposition. A new kind fails the build (our own and generated types) or the required checks (types from an external crate that may add variants) until it has one. A message that settles a turn is never silently dropped. E1 E7 · U1 U9 · V9.
  2. R10 · Refused only where the Codex CLI survives the error; otherwise minimal. Never "method not found". E7 · U7 · V10; ref: the pinned CLI's observed behavior.
  3. R12 · Every conversion is declared and typed on both sides, with zero, one or many outputs per input variant. No typed message carries another message as a JSON string. E6 · U5 U9 · V12; ref: the node table in Program Design.
  4. R13 · State a conversion depends on has one declared owner. This covers receipts, pending items and approvals, turn ids and text already sent, plus their resets and acknowledgements. E1 E6 · U9 · V13.
  5. R14 · One definition per meaning. True duplicates merge; related terms keep one mapping between them; wire encodings stay unchanged. E4 · U5 · V14; ref: duplicate inventory.
  6. R15 · One ACP authority for the ACP the Router sends and the ACP it serves. E5 · U5 · V15.
  7. R16 · MCP tool schemas come from the same definitions; nothing is spliced at runtime. E5 · U5 · V16.
  8. R17 · Incoming bytes are still decoded and rejected with today's outcomes. A malformed reply after an effectful request gives OutcomeUnknown, after a read gives Protocol, and retires the connection. Messages the Router built itself are not re-checked. E2 · U1 U5 · V17.
  9. R18 · One job per crate; no orphan files. E11 · U6 · V18.
  10. R19 · No behavior change except named fixes of wrong shapes. U5 U6 U9 · V19.
  11. R20 · Every node is listed with its problems and its fix; no node is left converting by hand. E1 · U9 · V20.
  12. R21 · Every message's producer and consumer nodes are listed in one place, and the list matches the code. E10 · U10 · V21.
