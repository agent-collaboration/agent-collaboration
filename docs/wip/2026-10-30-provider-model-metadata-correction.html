Use provider defaults, and perform a reset when one is requested

Proposed correction to the existing Program Design. The native client stays unchanged. Provider interpretation stays in the injected adapters. The existing catalogue carries qualified model information instead of inventing a medium effort. This document does not report implementation or proof.

The governing Requirements U3–U5, Specification R3–R5 and Program Design remain the boundary: supported native operations reach the provider; unsupported, failed and uncertain outcomes remain distinct; the existing actor sends and preserves conversations. No menu extension, new process, store or general settings engine is proposed.

What the code actually does

The Host keeps model IDs and labels, and the native renderer supplies an empty effort list and defaultReasoningEffort: "medium" for every model. Codex uses that value as a real setting after selection. Its typed schema requires a nonempty string; null, omission and an invented unknown token do not solve this.

Claude's qualified legacy default choice is a real operation: its SDK receives applyFlagSettings({effortLevel:null}). The SDK contract says this resets to the model default, rather than restoring a saved preference or keeping the current value. Cursor's existing cursor/list_available_models returns per-model options with an actual vendor-selected default value. Neither source justifies a universal medium.

Absence is not a successful reset. Claude can confirm a model change while catching a failed effort reset, retaining the old pin and removing its effort option. Cursor omits parameters with fewer than two choices from its descriptors, while its setter can still accept a sole parameter value. A missing option therefore remains unknown; it is never converted to a successful no-op.

The changed path

  1. Provider evidence → injected adapter. Claude's existing same-process wrapper adds model metadata to its existing outgoing updates and declared session responses. It reads the addressed public session's advertised model IDs and modelInfos. Cursor's adapter supplies the existing extension method name and decodes its result. Runtime code contains no provider-name branches.
  2. Adapter → existing connection/session owner. Add a synchronous immutable trait contract for the metadata source and decoding. Its source is SessionMetadata | ConnectionRequest { method } | Unavailable; decoding returns per-model closed variants above. The existing connection owner performs the optional Cursor read once after initialization, with a bounded reply and shutdown cancellation. No detached worker, rescan, prompt or retry is added. Each session intersects the result with its own actually advertised model IDs.
  3. Session owner → existing Host catalogue → native model/list. Carry the qualified descriptors in the existing settings snapshot/watch path. Native projection uses exact provider values and descriptions. It removes the hardcoded medium and the unqualified provider-default row. Unknown descriptors produce no selectable native row. Before metadata is available the list is empty; opening the existing model picker fetches again. Never copy one model's current effort onto other models.
  4. Native setting → existing actor → provider. The complete native mask's null effort resolves to the selected model's qualified default/reset value. Explicit values use the same fresh catalogue validation. Model is applied before effort, as today; later failure preserves the confirmed model effect and reports failure or uncertainty. Sparse omission/null still preserves effort. Unknown reset capability refuses before setting dispatch.

Bootstrap constraint: Codex awaits model/list before resume. With an empty list and no explicitly configured model it exits with “No models are available” (app_server_session.rs:698–784). Empty metadata is therefore not a generally healthy startup fallback. The candidate must qualify a truthful initial model/default action before claiming that path works. A model-list error or an unqualified custom launch must retain this exact limitation; the active-turn metadata isolation rule does not prove startup availability.

Claude: a reset must have a real implementation

Effort-capable models use the stock legacy default choice and supported levels. They keep the stock setting path. Exact advertised IDs must join uniquely to public model information; missing or contradictory metadata stays Unknown.

For a qualified model explicitly reporting supportsEffort:false, the stock ACP method offers no effort control, while its public SDK still exposes the reset. The proposed provider adaptation exposes that real reset through a reserved adapter-owned config ID, codex-router-effort-reset, and value default. It is described as ResetOnly metadata; it does not fabricate an initial current effort or add an ordinary selectable effort level.

The existing public agent.setSessionConfigOption method is decorated on the owned instance. Stock runAcp() dispatches through that instance method on each request. All ordinary IDs delegate unchanged. The reserved reset ID requires an exact live session/query and positively qualified model, then awaits that same query's public applyFlagSettings({effortLevel:null}) once. Only confirmed success clears the public pin bookkeeping and reports the actual default state. No SDK call runs merely to discover metadata.

Before the reset succeeds, current effort remains unknown/absent. After success, the response can include the adapter's reset-only option with confirmed currentValue: "default", so the existing setting executor can validate its result. A replaced/closed session or changed model invalidates publication. Any reset exception is conservatively marked outcome-unknown through a versioned adapter error annotation; the existing setting executor converts that to its existing unresolved-setting state. There is no retry, rollback, false acknowledgement or automatic reconstruction of the query.

This is a bounded expansion of the private provider adapter from metadata annotation to one public SDK setting operation. The native client, external process count and session owner stay the same. It must be rejected if the declared public method or SDK cannot support this boundary without private patching or duplicated lifecycle logic.

Cursor: use returned values; retain unknowns

Only a unique qualified effort descriptor supplies choices and the vendor default value, which must be one of those choices. Existing explicit-effort and thinking disambiguation rules remain. Missing, ambiguous, duplicate, malformed and unrecognized descriptors remain Unknown. The extension result is not permission to infer hidden one-choice parameters, change models to discover them or substitute a saved session value for a vendor default. Such rows remain unavailable to the native picker until positively qualified.

Why this boundary

Chosen direction: transport real provider descriptors and use the existing setting executor, with one qualified Claude reset adaptation. Maintainers pay for a typed metadata payload, an optional Cursor read and a small public-method decorator. The user gains truthful default choices and a real reset result. A universal constant, current-value substitution or zero-effect absence guard is smaller but cannot satisfy the requested behavior. A new settings service or client fork adds ownership the task does not need.

Accepted limit: unknown Cursor descriptors cannot be represented as usable native model rows. This preserves uncertainty rather than claiming unsupported choices work. Existing unsupported service tiers, permission controls, naming, context usage and other inventoried surfaces remain separate obligations; this correction does not retire them.

What must falsify the implementation

Permanent controlled tests must feed real TypeScript-produced metadata into the Rust decoder; exercise exact default/reset tokens, unknown/duplicate models and independent skill health; retain normal setting ordering and partial effects; force an SDK reset rejection, retirement and changed model; and reject a false current default before reset. Native WebSocket tests must show complete-null reset versus sparse preservation and zero prompt after an unresolved reset. These stand-ins do not qualify the provider.

The existing TypeScript/Rust/wterm route must then drive unchanged Codex model selection and a subsequent prompt for Claude, including Haiku, and a qualified Cursor model. Effective settings, actual native responses, provider effect and same-byte original captures must agree. No hardcoded medium, echo, successful model-only result or missing effort option can close that proof.
