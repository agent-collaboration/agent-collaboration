Authorize a private temporary settings file, or keep routed Claude inference on hold

Decision for Sun, through Station Chief. The Host-selected Router route needs a settings tier above ordinary user/project/local settings. The committed Q0 candidate puts the real local admission token in inline SDK settings; the qualified SDK serializes those settings onto the native child's command line. That candidate is held. No Q0 Host or provider session has run, and its Q2 build stopped before compilation.

I recommend the documented SDK settings-file path, with the narrow ownership and limits below. It keeps token values out of argv and retains the same vendor query/reader. It introduces a temporary credential-bearing file, so this is a security/storage decision the current implementation scope does not settle.

What the code establishes

Environment-only injection does not preserve the route against later ordinary settings. The public SDK settings tier does; however, object settings become --settings <JSON>. The SDK also formats its arguments for debug logging before a custom-spawn hook, so rewriting args only at that hook is too late. No public settings-env interpolation or pre-start secret-reference option was established. Managed policy stays higher priority and is not bypassed.

Option A — a private temporary settings file

Gain: preserve the selected URL and actual bearer through ordinary settings without placing token-bearing JSON in argv. Use the existing public Options.settings: absolutePath; the SDK passes that string unchanged. Keep normal home, normal sources and managed-policy precedence.

Proposed owner: the existing qualified Claude wrapper owns this derived, process-lifetime projection. The Host remains the authority for the original URL/token. The wrapper creates one owner-private temporary directory and immutable owner-only settings files before delegating session creation, passes their paths through the public API, and keeps them available while any vendor query/recreation may read them. It uses the existing shutdown/disposal path to remove its exact files after the vendor is disposed. No global cache, durable preference, credential database, second process/controller, query or reader is added.

Cost and limit: maintainers must implement and prove this small file lifetime. Abrupt termination such as SIGKILL cannot run the wrapper's cleanup; private files may remain until explicit task cleanup or OS temporary-storage cleanup. This option does not promise secure erasure or invent a background scavenger. Sun accepts that temporary credential-on-disk boundary, or declines it. No file is created before that decision.

Required proof: the real shipped entry keeps the Host binding, model-config fallback and unrelated settings; the file has the required permissions and lifetime; a faithful SDK spawn boundary receives a settings path and no token-bearing argv/debug string; normal disposal removes the exact owned files; failure leaves no untracked file or delegated effect. A real isolated Host must then produce a positive Claude audit window, genuine ordinary and selected-skill/image replies, and normal CLI exit. Existing J1/J2/J3/native/reverse obligations remain.

Version limits: stock ACP can turn a settings path back into an object when an explicit provider/gateway override is active; the qualified Host route must not combine with that mode. SDK settings-path plus its separate sandbox option is unsupported at this pin. New actual callers of those shapes return to design rather than being coerced. The file remains available beyond spawn; deleting it at spawn return is not justified.

Option B — keep the affected inference path on hold

Gain: introduce no new credential file or process responsibility. Cost: routed Claude ordinary/skill inference and final bridge readiness stay blocked. Source inventory, already proven refusal recovery and independent verifier review can continue; none substitutes for the missing real integration.

Where the agents stand

The 🦁 Lead recommends A with the explicit private-file lifetime and crash-residue limit. The 🦉 Advisor confirms the public path is source-feasible and retracts its earlier incomplete inline-settings advice; it requires an owner decision on the new storage responsibility. The 🔎 Reviewer found S1 and requires a boundary decision before the next real run. The 🔬 Verifier and 🐒 Implementer are held with no active action or cleanup dependency. No one claims routed inference is working.
