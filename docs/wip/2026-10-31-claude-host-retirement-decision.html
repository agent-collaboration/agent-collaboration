Give the qualified Claude wrapper five seconds to clean up before forced termination

Decision for Sun through Station Chief. Recommendation: A. The private temporary settings-file approach is approved. A newly checked production path prevents its promised normal cleanup: Router retirement immediately sends SIGKILL to the wrapper and its children. The existing ten-second supervisor timeout only bounds joining the runtime; it gives the provider no grace. Without a correction, valid token-bearing files would remain after ordinary shutdown, not only crashes.

A — bounded grace selected by the existing injected provider behavior

Gain: make the approved cleanup possible on the actual Host path. Keep the connection task as the sole process owner. Add one pure shutdown-policy value to its existing consumer-owned trait; the concrete qualified Claude adapter supplies the bounded grace and other adapters preserve immediate retirement. No provider-name branch, second controller, signal poller, SDK process or store.

Cost: a change to the shared runtime's internal lifecycle contract and its trait consumers. Qualified Claude retirement can take up to five seconds, within the existing ten-second supervisor bound. A timeout still invokes the existing forced group kill and leaves the accepted private residue; it is reported as failed cleanup. The supervisor currently returns on the first failure, skipping later bindings and drains. A must also retain the first failure while continuing retirement of every binding and the existing catalog/live-operation drains, then report failure after those attempts settle. This is a further bounded change to its shutdown error handling; a slow Claude child must not skip Cursor cleanup. Maintainers must prove timely cleanup, forced fallback and continued draining after that failure.

Required proof: a permanent integration case enters the real provider runtime's shutdown() with the shipped wrapper and a harmless SDK child, then observes actual exit and settings-file removal. A held child proves no premature deletion; a stuck child proves bounded forced termination and an explicit failed-cleanup result. A differing injected implementation proves the unchanged immediate policy. A supervisor case forces one provider's grace failure and proves the other binding and both existing drains still run before the retained error is returned. Existing retirement/admission/native/reverse tests remain required.

B — accept private residue on every ordinary Host retirement

Gain: preserve current Host termination timing and avoid the runtime lifecycle change. Cost: broaden the accepted storage risk from crash residue to normal residue and accumulation. The token can remain valid. This would require rewriting the cleanup obligation and removing any wrapper-only machinery that no longer earns its cost. No automatic scavenger or token rotation is included.

The owner's AGENTS instructions say to ask before changing agreed behavior, contracts or security boundaries. This is a discovered production-path contradiction, not another request to approve the already chosen temporary file.
