Sessions and Quota — one dialog system

A single reusable dialog component, applied consistently. Start a session in one form. Inspect an existing session in one dialog. Choose a machine inside that form.

The terminal views below are interactive HTML prototypes with invented session data. They are not screenshots or proof of an iocraft implementation. Development is underway; these prototypes remain illustrative. Compiled screenshot evidence will be presented separately. The proposal is based on origin/main at ffced1c1.

Try the shared component

Switch the content and terminal size. The same header, frame, body, action row, focus treatment and spacing apply to every example. Select Show component regions to see the reusable parts.

What the component system owns

The shared system lives in codex-router-tui. Every TUI menu and filter uses it; at most one dialog is active. SearchSelect filters choices inside the current form, never by nesting another dialog. Sessions and Quota both consume it. They supply content and actions; neither draws a second frame or implements a separate modal input policy. The prototype below illustrates the standard; adopting it across product callers is implementation work still to do.

Content sizing and viewport limits; margins, padding and border; modal focus and restoration; keyboard routing; the action row; overflow; accessible title. A caller cannot create another full-height frame around its content. Which machine is selected, source verification, session identity, pending work, errors, and what Start / Resume / Fork means. The dialog does not discover machines, launch a provider or retry an uncertain action.

Responsive sizing is part of the component

Default: clamped percentages on both axes. The editable example prefers 80% width and 60% height, each bounded by minimum/maximum sizes and the actual viewport. Width and height are independent parameters. A dialog can fit its content, occupy a chosen percentage of the available screen, or clamp that preferred size between minimum and maximum limits. Available space is measured after outer margins; the viewport remains the final cap, even if it is smaller than the configured minimum.

ModeWidth exampleHeight example

Resize recalculates the layout without resetting the form or its focus. The header and action row remain visible; extra height belongs to the body. A percentage sets the preferred size; minimum and maximum bounds clamp it before the actual viewport applies its final cap. The example limits above are adjustable component parameters, not rules embedded in individual screens.

No empty “Launch options” section. The old label in this proposal referred only to extra CLI arguments. The New session form shows no disclosure when there are none; supplied arguments can appear as ordinary secondary metadata.

Quota belongs to the same system

The current three-column grouping stays: Account · Status and counts · Quota. The first column gets useful width and wraps the full name, with provider directly below. Status, client/reset counts and credits stay in the middle. Routing reason, weekly, five-hour and pace information stay on the right. All figures below are invented examples, not the owner’s accounts.

Names wrap inside the Account column instead of being hard-capped at 13 or 17 cells. A permanent selector gutter keeps all three columns in the same positions when selection changes. Weekly and five-hour windows remain vertically aligned in the Quota column; they are not spread across separate columns. A balance such as 62.5k credits replaces a raw long decimal in the list. Details retain readable precision and all existing information. No unrequested information is dropped to achieve a row limit.

Folder scope, provider/source/runtime filters, updated/created sorting, search and all existing eligible actions remain. This redesign changes layout and shared controls, not those capabilities. Existing extra CLI arguments remain supported when supplied; empty metadata is not presented as a settings page.

A shorter New session flow

A list of actual sessions. New session is a header action, rather than a fake session with blank status and dates. One compact form shows the client, target machine and working directory. Machine choices expand within the form; the field already has a sensible default. Start verifies and uses the chosen destination. A pending or failed check stays in the same form, with no silent machine fallback.

Existing sessions: Enter opens Details. Resume, Fork and Copy ID are grouped there. Fork confirmation replaces the dialog body in place; it does not stack another full-size page.

The owner selected one form, then Start. Machine and directory are visible before launch. Searchable machine choices stay inside that form; selecting one never opens a second dialog.

How the components fit

Committed filters, New draft, captured session identity and existing launch/source commands. One active frame: header, intrinsic body viewport, action row. Inline searchable fields; fixed selector gutter. Account identity, observations, policy/floor/reset workflows and existing command ports.

The shared crate owns layout and interaction. It never launches sessions, changes policy or resets an account. Open the structural design for the component view, entry-to-effect path, entity bindings and requirement-to-owner/proof table.

What went wrong in the current implementation

The existing shared components were not made into a consistently used system. These are source findings, not guesses from appearance.

What must hold before calling it fixed

  • All Sessions and Quota dialogs—including New session, Details, machine selection, filters, Help and confirmations—use the same shared dialog system.
  • Actual iocraft screenshots at wide, compact and narrow sizes demonstrate content sizing, one title and consistent action placement.
  • Keyboard, mouse, focus restoration, pending work, errors and constrained-height scrolling behave through the real component.
  • Native session identity, remote source verification, launch semantics and uncertain-outcome protections remain intact.

The Activity / Following proposal, board redesign and Host migration are outside this UX correction. Quota is explicitly included by the owner’s later instruction, with its information and features preserved.
