Codex CLI → ACP: what is mapped, what is known, what is missing

The bridge is not ready across the whole CLI surface. Earlier real skill execution passed for Claude and Cursor. The current candidate passed Sonnet/low and Haiku/low selection and current-value readback, but both following skill/image prompts failed to produce their required replies. The underlying provider error is unresolved. Other command paths and displayed information still need qualification.

This inventory follows the unchanged CLI into the bridge and names who owns the information. Provider-specific interpretation belongs behind injected code; the native facade owns protocol adaptation. Local CLI actions stay with the CLI. Unsupported, unavailable and unknown are different outcomes.

How to read the inventory

The denominator includes 65 slash definitions, 179 client-request declarations, 86 server-notification declarations, 9 server-request declarations and 1 client-notification declaration. Feature gates mean these are not all visible menu items. References are not proof that a path is called or handled.

Enumeration is broader than completed tracing. Named-hop and untraced rows remain open. Test-file mentions are discovery pointers. Source-only mappings are not passing runtime checks. A compatibility value is not automatically wrong, but it is not provider-derived information.

All 89 direct-request construction rows in the three scanned CLI crates now carry an entry, gate, consumed fields and error assessment; 15 still name a partial caller or provenance edge. The other protocol declarations include methods built elsewhere or mentioned only in a match. No direct reference is not proof of no use. The authenticated analytics backend is also distinct from the native account/usage/read thread-estimate RPC.

Failure handling is part of support. Cursor compact had a client-exit failure at c6 and has a later qualified recovery fix. The /rename refusal was exercised at 1d116128445d6dd690b73098925a4ff44b2c72b9: the unchanged CLI exited1, while the name/history stayed unchanged and no provider turn was sent.
