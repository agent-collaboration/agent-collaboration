# Provider-filter journeys

`capture-run.ts` drives `sessions-GRID` and `quota-GRID` from the literal catalogue.
The real PTY hosts six synthetic typed session records or four real isolated
SQLite account rows. It does not launch a session or contact a live vendor.

The journey enters each chooser with the existing bindings, checks the active
field/query/no-match, contextual Help and unchanged return, then apply/cancel,
counts, selected identities and Details. Quota also checks Disabled/Hidden choices
and Pool top/middle/bottom census with all ten rows covered across the poses.
A field's value must belong to its active dialog. Wrong providers, blank grids,
chooser-as-applied and open-Pool-as-closed controls reject.

Every plan binds source and prebuilt driver/product hashes, viewport and key mode.
Raw ANSI and actual libghostty cells are kept; optional original wterm DOM PNGs
are separate appearance evidence. Six grid definitions exist; report which were
actually driven. Unit tests, mounted frames, live captures and provider acceptance
remain distinct evidence. State/secrets must remain unchanged and the owning
fixture must observe only its permitted sealed GETs.

See `scripts/verification/tui/README.md` and the canonical compiled TUI recipe.
